# 功能规格：Dify AI 编排

**功能分支**：`codex/dify-ai-orchestration`

**创建日期**：2026-10-27

**状态**：草稿

**输入**：项目改造为后端负责数据处理和业务规则，Dify 负责 AI 编排；先在本地环境接入已有 Dify 服务，不影响生产环境。

## 用户场景与测试

### 用户故事 1 - AI 整理交由 Dify 编排（优先级：P1）

用户通过 AI 文字、网页、文档、截图或互联网候选采集知识时，后端完成内容提取、密钥脱敏、账号隔离、计费门禁和事务控制，再调用识海自己的 Dify 知识整理工作流生成结构化知识。用户得到与现有流程一致、可复核的富文本知识。

**优先级理由**：知识整理是识海最核心的 AI 能力，先迁移它可以在不改变用户业务结果的前提下降低提示词和模型耦合。

**独立测试**：在本地 Dify 中运行 `shihai-knowledge-organizer`，提交一段已脱敏文本，后端应生成通过现有结构校验的知识条目；Dify 不可用时不得伪造成功或部分写入。

**验收场景**：

1. **给定** 用户已授权外部 AI 且测试计费门禁满足，**当** 用户提交 AI 文字、网页、文档、截图或互联网候选，**那么** 后端只向 Dify 发送脱敏后的文本和必要元数据，并保存 Dify 返回且通过后端校验的知识。
2. **给定** Dify 返回缺失标题、摘要、分类、标签或正文无有效内容的 JSON，**当** 后端解析结果，**那么** 整次导入失败且不创建部分知识。
3. **给定** Dify 超时、拒绝连接或返回非成功状态，**当** 用户执行 AI 整理，**那么** 后端释放或按既有规则结算点数，并向用户返回统一 AI 服务不可用提示，不暴露 Dify 内部信息。

---

### 用户故事 2 - 小识对话使用 Dify 编排（优先级：P1）

用户与“小识”聊天时，后端继续负责知识检索、候选账号校验、通用回答与联网判断、引用校验、会话持久化和点数结算；Dify 负责知识回答、通用回答、检索计划、联网回答及流式文本生成。

**优先级理由**：聊天依赖知识检索和业务约束，必须与知识整理同时验证 AI 编排迁移不会破坏引用、流式输出和点数结算。

**独立测试**：本地启动后端并配置识海 Dify 聊天工作流后，问答可以命中当前账号知识、流式显示、保存历史并返回真实引用；无知识时进入通用对话，实时信息不足时提示联网。

**验收场景**：

1. **给定** 当前账号存在匹配知识，**当** 用户提问，**那么** 后端检索候选并交由 Dify 生成回答，后端仅保留属于本轮候选的引用后写入历史。
2. **给定** 当前账号没有匹配知识，**当** 用户提问，**那么** 小识先使用 Dify 通用回答；通用回答无法可靠完成时才提示联网。
3. **给定** Dify 流式连接中断或返回空文本，**当** 用户等待回答，**那么** 不得把失败回答保存为成功历史，并按既有计费规则释放或结算已完成的联网步骤。

---

### 用户故事 3 - 本地和回退配置可控（优先级：P2）

开发人员可以通过环境变量选择本地 Dify 或 DeepSeek 直连，配置中不出现真实密钥；Dify 不可用时可显式切回已有 DeepSeek 实现，生产默认配置不因本次改造而改变。

**优先级理由**：本地迁移必须可控、可回滚，且不得让开发配置意外进入生产。

**独立测试**：使用 `provider=dify` 启动时调用识海 Dify 工作流；使用 `provider=deepseek` 时保持现有调用。缺少对应 Dify API Key 时启动或首次调用失败关闭，不静默改投其他提供商。

**验收场景**：

1. **给定** 本地环境只设置识海 Dify 工作流密钥，**当** 开发者启动应用，**那么** AI 整理与聊天使用 Dify。
2. **给定** 开发者显式选择 DeepSeek 直连，**当** 执行 AI 整理或聊天，**那么** 保持现有 DeepSeek 行为和测试契约。
3. **给定** 仓库执行密钥扫描，**那么** 源码、SDD 文档、测试夹具和日志中不得出现真实 Dify 或 DeepSeek 密钥。

### 边界情况

- Dify 返回代码块包裹的 JSON、空输出、错误事件、超时事件或流中途断开。
- 同一幂等键在 Dify 超时后被重试，后端不得重复扣点或重复写入知识。
- Dify 输入超过工作流字符上限，或 OCR、解析、脱敏阶段已失败。
- Dify 工作流被停用、删除、替换模型或更换 API Key。
- 多个浏览器会话并发聊天，各自账号、知识候选和会话历史不得串流。
- 测试和正式环境同时存在 Dify 配置时，应用只使用当前环境显式指定的识海工作流。
- 生产尚未完成 Dify 专用密钥、网络和点率验证时，不得自动切换到 Dify。

## 需求

### 功能需求

- **FR-001**：后端必须继续拥有账号身份、知识正文、附件、OCR、文档解析、网页单页采集、AI 外发授权、密钥脱敏、报价、预留、结算、释放、幂等、事务和审计。
- **FR-002**：Dify 只负责提示词、模型选择、条件编排和文本生成，不得直接写识海业务数据库、管理账号或修改点数。
- **FR-003**：识海必须使用独立于拾题和其他应用的 Dify 应用、工作流和 API Key。
- **FR-004**：发送给 Dify 的内容只能包含后端已授权并脱敏的文本、问题、短历史和候选证据，不得包含密码、Cookie、会话标识、支付密钥、原始文件或未脱敏 OCR 全文。
- **FR-005**：Dify 调用必须使用当前账号的稳定标识作为外部用户键，但该键不得包含邮箱、密码或其他直接身份信息。
- **FR-006**：知识整理工作流必须返回可被后端严格映射的结构化结果；缺失标题、正文、摘要、分类或标签时整次导入失败。
- **FR-007**：聊天工作流必须支持知识回答、通用回答、检索计划、联网回答和流式回答，并由后端校验最终引用与业务状态。
- **FR-008**：Dify 请求必须有显式连接、读取和总响应超时，以及有限次数的安全重试；不可重试的业务拒绝不得重试。
- **FR-009**：Dify 不可用时不得绕过 AI 外发授权、计费门禁、幂等和知识写入规则。
- **FR-010**：Dify 内部错误、工作流状态、运行标识和上游响应不得原样返回浏览器或写入用户可见日志。
- **FR-011**：AI 提供商必须通过环境变量显式选择，支持 `dify` 和现有 `deepseek` 回退；缺少所选提供商配置时必须失败关闭。
- **FR-012**：本地默认接入已有 Dify 服务，生产配置不得因本次改造自动启用 Dify。
- **FR-013**：应用必须记录不含正文和密钥的结构化调用结果，包括提供商、操作类型、耗时、成功状态和脱敏错误码，便于排障与审计。
- **FR-014**：Dify 工作流和密钥的名称必须使用识海专用前缀，且密钥只能来自环境变量或受管密钥服务。
- **FR-015**：改造不得改变现有知识导入、聊天、计费、搜索、引用校验和账号隔离对用户承诺的业务结果。

### 关键实体

- **AI 编排配置**：提供商、服务地址、工作流密钥引用、超时、重试和启用状态。
- **知识整理请求**：来源类型、脱敏文本、条数上限和当前账号外部键。
- **知识整理结果**：标题、富文本 Markdown、摘要、分类、标签和校验状态。
- **对话编排请求**：操作类型、问题、短历史、候选证据和当前账号外部键。
- **对话编排结果**：回答文本、引用候选或检索短语、联网需求、工作流运行标识和完成状态。

## 成功标准

### 可衡量结果

- **SC-001**：在本地 Dify 正常运行且模型可用时，100% 的现有 AI 整理自动化契约用例在 Dify 模式下得到与 DeepSeek 模式相同结构的知识结果。
- **SC-002**：在本地 Dify 正常运行且模型可用时，知识回答、通用回答、检索计划、联网回答和流式回答五类对话操作均至少通过一条端到端验证。
- **SC-003**：Dify 超时、空响应和畸形输出三类失败均不会创建知识、伪造引用、重复扣点或写入成功会话，自动化覆盖率为 100%。
- **SC-004**：源码、配置示例、SDD 文档和测试夹具中的真实 Dify/DeepSeek 密钥数量为 0。
- **SC-005**：切换提供商只需修改环境变量和重启本地应用，不需要修改 Java 业务服务或前端代码。
- **SC-006**：现有后端全量测试、前端 lint、TypeScript 检查和构建在改造后保持通过。

## 假设

- 本地 Dify 版本为 1.13.3，并已安装可用的 DeepSeek 模型插件。
- 本地 Dify 工作流通过识海独立 API Key 调用，不复用拾题或其他项目的工作流和密钥。
- 本次只改造本地运行配置和代码适配层；生产 Dify 部署、网络策略和正式密钥轮换需另立发布任务。
- 现有知识整理和聊天接口、SSE 协议、数据库结构和前端行为保持不变。
- Dify 工作流输入字符上限与后端现有脱敏文本上限相容，超限由后端提前拒绝。
