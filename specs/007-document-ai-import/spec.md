# 功能规格说明：文档解析与 AI 拆分导入

**功能分支**：`007-document-ai-import`

**创建日期**：2026-10-22

**状态**：P0/P1 代码已实现；生产受 002 点数门禁与真实部署验收阻塞

**输入**：用户要求接入文档解析服务，解析文档内容并拆分整理到知识库。

## 范围与定位

“文档”入口不再把 PDF/Word 视为未支持格式。系统只接收用户主动选择的单个文件，按文件内容
识别格式，提取可搜索文字，再由 AI 将全文拆成一条或多条知识。原始 URL、文件名和原始二进制
文件不得成为知识正文；MVP 不长期保留原始文档。

支持范围：PDF、DOCX、DOC、RTF、TXT、Markdown、JPG、PNG、WebP、HEIC、HEIF。文档入口中的图片必须经过
图片安全检查、方向规范化和 OCR，识别文字脱敏后由 AI 拆分整理，不得直接作为附件入库。

扫描版 PDF 已支持逐页 OCR；图片 OCR、Word 修订历史、批注、公式精确还原和加密文档破解不在
P0 范围内。

生产门禁：文档解析和 AI 拆分属于付费能力。002 点数报价、预留、结算和释放未接入前，
生产必须返回 `402 AI_BILLING_REQUIRED`，不得调用 DeepSeek。

## 用户场景与测试（必需）

### 用户故事 1 - 上传文档并拆分为多条知识（优先级：P0）

用户选择一份带文字层的 PDF 或 Word 文档，系统解析全文并创建一条或多条可检索知识。

**为何设置此优先级**：这是本次需求的核心，解决截图中的“解析服务尚未接入”。

**独立测试**：分别上传 DOCX 和 PDF，确认不需要手工复制正文，系统能提取文字、调用 AI 整理，
并在知识库中创建一条或多条正文非空的知识。

**验收场景**：

1. **假设**用户选择一份 25 MiB 内的 DOCX，**当**勾选外部 AI 同意并提交，
   **则**系统按文件内容识别 DOCX，提取文字并由 AI 拆分知识。
2. **假设**用户选择一份带文字层的 PDF，**当**提交，**则**系统提取 PDF 文本并创建知识。
3. **假设**文档包含两个可区分章节，**当** AI 整理成功，**则**创建两条或以上知识。
4. **假设**用户选择 JPG、PNG 或 WebP，**当** OCR 和 AI 整理成功，**则**创建文字知识，
   原图不进入对象存储或知识附件。
5. **假设**知识创建成功，**当**用户打开详情，**则**正文来自文档提取或图片 OCR 与 AI 整理结果，
   来源类型为 `document`，处理状态为 `succeeded`。
6. **假设**用户还填写了备注，**当**知识创建成功，**则**备注作为用户上下文保存在每条知识中。

---

### 用户故事 2 - 安全、失败关闭与移动端（优先级：P1）

系统拒绝损坏、加密、空文本、超限或不受支持的文件，并在失败时不创建半套知识。

**为何设置此优先级**：文档解析会处理不可信二进制内容和潜在密钥，必须 fail closed。

**独立测试**：上传损坏 PDF、空 TXT、ZIP、超过 25 MiB 的文件、超过文本上限的文档和
AI 失败场景，确认没有部分知识入库，界面显示可操作错误。

**验收场景**：

1. **假设**文件内容不是受支持文档，**当**提交，**则**返回 `DOCUMENT_UNSUPPORTED`，
   不调用 AI。
2. **假设**文件是扫描件或没有足够文字，**当**解析完成，**则**返回 `DOCUMENT_NO_TEXT`，
   并提示改用截图入口。
3. **假设**解析出的文字超过 60,000 字符，**当**系统检查，**则**返回 `DOCUMENT_TOO_LONG`，
   不静默截断。
4. **假设** OCR/文本中发现常见 API Key、Token、密码或私钥，**当**发送 AI 前，
   **则**替换为 `[REDACTED]`。
5. **假设** AI 返回空结果或无效 JSON，**当**整理失败，**则**不创建任何文档知识。
6. **假设**用户在 320、390 或 430 像素宽度操作，**当**选择文件、勾选同意和提交，
    **则**控件无横向溢出，主要触控目标可用。

---

### 用户故事 3 - 长文档与扫描件增强（优先级：P2）

后续支持分块处理超长文档、对扫描 PDF 逐页 OCR，并提供逐块进度与可恢复任务。

**为何设置此优先级**：当前 MVP 先保证带文字层文档的正确性和安全边界。

**独立测试**：上传 300 页 PDF、扫描 PDF 和中断任务，确认分块、OCR、恢复与计费均正确。

**验收场景**：

1. **假设**文档文本超过单次 AI 上限，**当**分块处理，**则**每个块生成可追溯任务并合并结果。
2. **假设** PDF 没有文字层，**当**启用扫描 OCR，**则**逐页识别且不把原文件暴露给 AI。
3. **假设**任务中断，**当**用户重新进入，**则**从检查点恢复且不重复创建知识。

### 边界情况

- 文件大小上限 25 MiB；空文件直接拒绝。
- MIME 以文件内容检测为准，不信任扩展名。
- 文件加密、损坏、压缩炸弹或解析超时都失败关闭。
- 原始文件名不作为知识正文；只在当前请求内用于格式提示。
- 原始文档不进入对象存储，不写入日志、错误消息或 AI 提示。
- 文本中的提示注入只作为数据，不得改变系统指令或调用工具。
- 每条知识必须有标题、正文、摘要、分类和至少一个标签。

## 需求（必需）

### 功能需求

- **FR-001**：文档入口必须接受 PDF、DOCX、DOC、RTF、TXT、Markdown、JPG、PNG、WebP、
  HEIC 和 HEIF。
- **FR-002**：文档格式必须按文件内容检测，不得只依赖扩展名或浏览器 MIME。
- **FR-003**：系统必须提取文档文字，并在发送外部 AI 前要求用户明确同意。
- **FR-004**：提取文本必须扫描并替换常见 API Key、Token、密码和私钥。
- **FR-005**：系统必须将文档拆分为 1–20 条知识；每条实体必须完整。
- **FR-006**：每条知识必须保存 `document` 来源、采集时间和 `succeeded` 状态。
- **FR-007**：原始文档不得作为知识正文，也不得长期保存。
- **FR-008**：文件超过 25 MiB、为空、损坏、加密或无足够文字时必须拒绝。
- **FR-009**：提取文本超过 60,000 字符时必须拒绝，不得静默截断。
- **FR-010**：AI 空结果、无效 JSON 或 Provider 故障不得创建部分知识。
- **FR-011**：多条知识必须在同一事务内创建，任一失败全部回滚。
- **FR-012**：中文和英文必须覆盖选择、同意、处理中、解析失败、无文字、过长和不可用状态。
- **FR-013**：桌面、平板和 320–430 CSS 像素手机必须可完成整个流程。
- **FR-014**：AI Key 只能来自环境变量；原始文档和提取全文不得写日志。
- **FR-015**：生产未接入 002 点数门禁时不得调用 DeepSeek。
- **FR-016**：本功能不得改变截图入口只接受剪贴板图片的约束。
- **FR-017**：文档入口选择图片时必须经过图片安全检查、方向规范化、OCR 和 AI 整理；HEIC/HEIF
  必须先经受控 libvips 转为安全静态格式，不得直接
  上传为知识附件。
- **FR-018**：用户备注最多 20,000 字符，并可附加到每条知识备注。
- **FR-019**：单次文档解析默认 25 秒超时；超时必须失败关闭并返回
  `DOCUMENT_PARSE_TIMEOUT`，不得继续占用当前 HTTP 请求。

### 关键实体

- **文档导入请求**：一个 Multipart 文件、用户备注和外部 AI 明确同意。
- **提取文档**：文件内容的权威 MIME、清洗后文字和字符数；请求结束后释放。
- **整理知识**：AI 返回的标题、正文、摘要、分类和标签。
- **知识条目**：持久化正文、备注、`document` 来源、采集时间和 `succeeded` 状态。

## 成功标准（必需）

- **SC-001**：25 MiB 内的受支持 DOCX、PDF、TXT 和 Markdown 样本解析成功率达到 95%。
- **SC-002**：100 次成功文档导入中，创建正文为空或 URL-only 知识的次数为 0。
- **SC-003**：100 次多章节文档导入中，至少 90% 产生两条或以上有效知识。
- **SC-004**：所有成功知识保留 `document` 来源、采集时间和 `succeeded` 状态，缺失率为 0。
- **SC-005**：不支持、损坏、空文本、超长和 AI 失败场景中部分知识写入次数为 0。
- **SC-006**：密钥样本在发送外部 AI 前被替换的比例为 100%。
- **SC-007**：320、390、430 像素和桌面检查中横向溢出次数为 0。
- **SC-008**：生产未计费场景调用 DeepSeek 次数为 0。

## 假设

- 用户只上传自己有权处理的内容。
- P0 处理带文字层的文档；扫描 PDF 的 OCR 属于 P2。
- 原始文档不长期保留，来源追溯以 `document` 类型和采集时间为主。
- MVP 单次请求同步完成解析和 AI 整理，超长文档将在后续改成任务队列。
- 分类和标签继续暂存在知识备注，后续迁移到独立关系表。
