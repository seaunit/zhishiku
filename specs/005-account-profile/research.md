# 阶段 0 研究：账户菜单与个人资料

**功能**：`005-account-profile`

**日期**：2026-10-22

## 决策 1：显示名称存入现有账户记录

**决策**：在 `owner_account` 增加 `display_name`，不创建新的 profile 表。

**理由**：资料与认证账号是一对一关系，复用现有账号能减少连接和生命周期复杂度。显示名称
不影响登录身份，邮箱继续作为唯一登录标识。

**替代方案**：独立资料表增加一次关联和孤儿风险；把昵称写入 locale 或 UI 本地存储会导致
换设备丢失，不采用。

## 决策 2：MVP 不提供头像上传

**决策**：头像继续使用显示名称首字或邮箱首字。

**理由**：用户本次要求的是资料查看编辑和退出入口。头像上传会引入格式验证、libvips、对象
存储、清理、配额和隐私处理，超出本轮核心缺陷修复。

**替代方案**：复用富文本图片上传会错误绑定知识条目；直接保存 data URI 会放大数据库和注入
风险，不采用。

## 决策 3：资料接口只依赖当前认证会话

**决策**：使用 `GET /api/v1/profile` 与 `PATCH /api/v1/profile`，服务端从
`Authentication` 找到账号。

**理由**：避免客户端提交 `ownerId` 导致越权；与现有知识、附件和搜索的账号隔离方式一致。

**替代方案**：`/owners/{id}` 需要额外权限判断且暴露内部标识，不适合当前单用户会话页面。

## 决策 4：显示名称采用 Unicode 字符长度

**决策**：规范化空白后限制 1–40 个 Unicode code point，拒绝控制字符和 `<`、`>`。

**理由**：中文、英文和常用符号都能保存，同时避免 HTML 片段和控制字符进入界面。Vue 默认
文本插值仍提供输出转义，服务端验证作为第二层防线。

**替代方案**：只按 UTF-16 长度会错误限制部分字符；允许任意 HTML 依赖前端清洗风险更高。

## 决策 5：退出确认是独立可复用对话框

**决策**：新增轻量确认对话框，后续可用于其他破坏性操作；退出确认后再调用现有 logout。

**理由**：原生 `confirm` 无法保持现有视觉、双语和无障碍一致性。退出需要明确说明和键盘焦点。

**替代方案**：菜单项直接退出仍会误触；依赖浏览器 confirm 无法做品牌化和稳定测试。

## 决策 6：同步更新原型

**决策**：原型增加账户菜单、资料页和退出确认，正式 Vue 页面按同一结构实现。

**理由**：项目宪法要求原型是视觉和交互事实源，不能只改生产前端。

## 已解决的未知项

- 资料字段：显示名称可编辑，邮箱只读，头像首字生成。
- 退出确认：需要。
- 语言偏好：继续使用现有顶部切换，不在资料页重复。
- 存储：复用 `owner_account`。
