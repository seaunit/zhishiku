# 功能规格说明：账户菜单与个人资料

**功能分支**：`005-account-profile`

**创建日期**：2026-10-22

**状态**：草案

**输入**：用户要求新增点击头像查看和编辑个人资料、退出账号的功能；现状是点击头像直接退出登录。

## 范围与定位

本功能把头像从“立即退出”改为账户入口。用户点击头像后可以查看当前账号、进入个人资料、
编辑显示名称，或通过明确的二次确认退出登录。

MVP 只支持编辑显示名称。登录邮箱只读，头像继续使用显示名称或邮箱首字。语言切换继续使用顶部
现有入口，本功能不新增第二套语言设置。

**不在范围内**：

- 修改邮箱、密码、找回密码、MFA、OAuth 绑定。
- 上传或生成头像，裁剪头像，支持动态头像。
- 注销账号、删除账号、导出个人数据、退出所有设备。
- 团队空间、账号切换、跨账号数据共享。
- 个人简介、电话、地址、生日、公司等扩展资料。

## 用户场景与测试（必需）

### 用户故事 1 - 从头像打开账户菜单（优先级：P1）

已登录用户点击头像时看到账户菜单，而不是立即退出。

**为何设置此优先级**：这是本次缺陷的直接修复；用户必须先有可控入口，才能进入资料或执行退出。

**独立测试**：点击头像后确认菜单出现、登录状态保持、页面未跳转，菜单包含“个人资料”和
“退出登录”。

**验收场景**：

1. **假设**用户已登录，**当**点击头像，**则**打开账户菜单且不会退出登录。
2. **假设**账户菜单已打开，**当**点击菜单外区域或按 `Esc`，**则**菜单关闭且焦点回到头像按钮。
3. **假设**用户使用键盘，**当**在头像上按 `Enter` 或空格，**则**菜单打开并可依次聚焦菜单项。
4. **假设**界面为中文或英文，**当**打开账户菜单，**则**显示当前显示名称、邮箱、个人资料和退出
   登录的对应文案。

---

### 用户故事 2 - 查看并编辑个人资料（优先级：P1）

用户从账户菜单进入个人资料，查看当前账号并修改显示名称。

**为何设置此优先级**：头像入口必须提供真正的资料能力，而不是只新增一个视觉菜单。

**独立测试**：修改显示名称并保存，刷新页面后仍显示新名称；取消编辑不会改变服务端数据。

**验收场景**：

1. **假设**用户选择“个人资料”，**当**页面打开，**则**显示头像预览、显示名称和只读登录邮箱。
2. **假设**用户把显示名称修改为合法的 1–40 个字符，**当**点击保存，**则**显示保存成功，顶部头像
   首字和账户菜单同步更新。
3. **假设**用户清空显示名称、超过 40 个字符或输入控制字符，**当**尝试保存，**则**显示当前语言
   的错误提示且不修改服务端资料。
4. **假设**用户修改后点击取消，**当**返回查看态，**则**输入恢复为当前已保存名称。

---

### 用户故事 3 - 明确退出登录（优先级：P1）

用户从账户菜单选择退出时，先看到确认提示，确认后才结束当前会话。

**为何设置此优先级**：退出是会话级操作，需要防止误触；这也保证头像点击不再产生破坏性结果。

**独立测试**：点击退出后取消，仍保持登录；再次退出并确认，进入登录页且受保护页面不可继续访问。

**验收场景**：

1. **假设**用户选择“退出登录”，**当**确认框出现，**则**文案说明会结束当前会话。
2. **假设**用户点击取消，**则**确认框关闭，当前会话和页面内容保持不变。
3. **假设**用户确认退出，**则**服务端会话失效并进入登录页。
4. **假设**用户在退出后使用浏览器后退，**则**不能继续读取受保护的资料内容。

### 边界情况

- 显示名称两端空白、连续空白和全角空格必须规范化后校验。
- 显示名称可以包含中英文、数字和常用符号，但不得包含 HTML 标签、脚本或控制字符。
- 邮箱始终只读，不能在资料页直接提交修改。
- 会话过期时，资料读取和保存必须提示重新登录，不得创建匿名资料。
- 多账号环境下，读取和保存只能作用于当前会话账号，客户端提交其他账号标识不得生效。
- 长显示名称和长邮箱不得把菜单或移动端布局撑出视口。
- 资料保存失败时保留用户输入，并允许重试。
- 连续点击保存不得创建重复账号资料或产生并发覆盖其他账号的数据。

## 需求（必需）

### 功能需求

- **FR-001**：点击头像必须打开账户菜单，不得直接退出登录。
- **FR-002**：账户菜单必须显示当前显示名称和只读邮箱。
- **FR-003**：账户菜单必须提供“个人资料”和“退出登录”。
- **FR-004**：账户菜单必须支持点击外部关闭、`Esc` 关闭、焦点返回和键盘操作。
- **FR-005**：个人资料页必须显示头像预览、显示名称和只读登录邮箱。
- **FR-006**：用户必须能够把显示名称修改为规范化后 1–40 个 Unicode 字符。
- **FR-007**：服务端必须拒绝空名称、超长名称、控制字符和类似 HTML 的标签输入。
- **FR-008**：保存成功后，资料页、顶部头像和账户菜单必须立即使用新显示名称。
- **FR-009**：刷新页面或重新登录后，已保存显示名称必须保持。
- **FR-010**：退出登录必须经过确认；取消不得改变会话或页面状态。
- **FR-011**：确认退出必须通过受保护的会话操作完成，并跳转到登录页。
- **FR-012**：资料读取和保存必须只作用于当前认证账号，不接受客户端账号标识作为授权依据。
- **FR-013**：资料页必须支持中文和英文完整文案、错误提示和保存状态。
- **FR-014**：账户菜单和资料页必须适配 320–430 CSS 像素、平板和桌面，主要触控目标至少
  44×44 CSS 像素。
- **FR-015**：本功能不得改变知识、附件、搜索、AI 授权、点数、支付或原拾题应用行为。

### 关键实体

- **账户资料**：当前登录账号的显示名称和只读邮箱；邮箱是登录身份，显示名称是界面身份。
- **账户会话**：决定当前账号资料读取和写入范围的已认证会话。

## 成功标准（必需）

### 可衡量结果

- **SC-001**：100% 的头像点击测试先打开账户菜单，直接退出次数为 0。
- **SC-002**：用户在 30 秒内可以从头像进入个人资料并找到显示名称编辑入口。
- **SC-003**：100 组合法显示名称保存后刷新仍保持一致，成功率 100%。
- **SC-004**：100 组空值、超长、控制字符和 HTML 标签输入均被拒绝，执行注入次数为 0。
- **SC-005**：100% 的退出取消测试保持原会话，100% 的退出确认测试使受保护接口不可继续访问。
- **SC-006**：账号 A 不能读取或修改账号 B 的显示名称，跨账号成功次数为 0。
- **SC-007**：320、390、430 像素、平板和桌面检查中，菜单溢出和主要操作遮挡次数为 0。
- **SC-008**：中文和英文下账户菜单、资料页、验证错误和退出确认均无未翻译文案。

## 假设

- 现有登录、注册、Spring Session 和 CSRF 规则继续有效。
- 显示名称只用于当前产品内身份展示，不进入搜索、AI、公开页面或支付资料。
- 头像继续由显示名称首字或邮箱首字生成，不要求上传图片。
- 资料保存采用当前账号的最后写入结果；本次不增加多标签页冲突对话框。
- 语言偏好继续由现有顶部语言切换管理，不在本次资料页重复编辑。
