# 功能规格说明：网页截图 AI 拆分导入

**功能分支**：`006-webpage-ai-import`

**创建日期**：2026-10-22

**状态**：P0/P1 代码已实现；生产被 002 点数门禁、真实 OCR 和生产部署验收阻塞

**输入**：用户明确要求“网页链接不是收录网页，而是 AI 帮截图拆分整理知识库”。

## 范围与定位

本功能遵守 [009 AI 辅助采集统一规则](../009-ai-assisted-capture/spec.md)：网页链接是非手动
采集入口，只能在 OCR、脱敏和 AI 整理成功后创建知识。

本功能修正网页链接入口的产品语义。用户提交一个公开网页 URL 后，系统只打开该页面一次，
对渲染结果截图，识别截图中的可见文字，再由 AI 将可见内容拆分、摘要、分类并生成标签，
最终创建一条或多条正文可检索的知识。URL 只作为来源元数据，不得成为知识正文，也不得创建
“只有网址、等待以后再看”的伪知识。

本功能不提供网页收藏夹、离线网页镜像、全文爬虫、站内遍历、分页采集或登录态页面抓取。

生产门禁：网页截图分析和 AI 拆分属于付费能力。当前分支保留 `SHIHAI_WEB_IMPORT_ALLOW_UNBILLED_AI`
供本地自动化使用，默认值为 `false`。002 的报价、预留、结算和释放尚未接入时，生产请求必须
返回 `402 AI_BILLING_REQUIRED`，不得调用 DeepSeek；不得用该变量绕过生产计费。

## 用户场景与测试（必需）

### 用户故事 1 - 网页链接变成多条知识（优先级：P0）

用户粘贴一个公开网页链接并提交，系统截图分析后把该页面整理为可立即检索的知识。

**为何设置此优先级**：这是本次需求修正的核心。若仍只保存 URL，功能没有完成知识整理目标。

**独立测试**：提交一个包含两个主题的公开页面，确认只请求该 URL，生成至少两条知识，
每条正文来自可见文字整理结果，且正文不等于 URL。

**验收场景**：

1. **假设**用户提交一个可公开访问的 HTTP/HTTPS 页面，**当**点击“AI截图拆分入库”，
   **则**系统只渲染该页面一次，并通过截图 OCR 获得可见文字。
2. **假设**截图包含两个可区分主题，**当** AI 整理成功，**则**创建至少两条独立知识，
   每条包含标题、正文、摘要、分类和自动标签。
3. **假设**知识创建成功，**当**用户打开详情，**则**正文显示整理后的知识文本，来源信息
   显示原始 URL 和采集时间。
4. **假设**页面只有很少可识别文字，**当**系统无法形成有效知识，**则**返回明确错误，
   不创建 URL-only 知识。

---

### 用户故事 2 - 单页边界与失败可解释（优先级：P1）

用户可以确认系统只处理自己提交的一页，并在截图、OCR 或 AI 失败时获得可操作提示。

**为何设置此优先级**：单页边界是“不使用爬虫”的可验证约束，失败语义决定用户能否安全重试。

**独立测试**：使用无正文页面、AI 超时、无效 AI JSON、私网 URL 和重定向 URL 分别提交，
确认没有知识写入、没有链接遍历，所有错误均可区分且不泄露密钥或页面凭据。

**验收场景**：

1. **假设** URL 指向本机、私网、链路本地地址或含登录凭据，**当**用户提交，
   **则**系统在渲染前拒绝。
2. **假设**页面重定向到非公开地址，**当**浏览器发现该请求，**则**请求被阻止，后端对最终 URL
   再次执行公开地址校验。
3. **假设**页面要求登录、主要靠 Canvas 或没有足够可见文字，**当** OCR 无法得到有效文本，
   **则**系统提示改用截图入口粘贴用户有权查看的页面截图。
4. **假设** AI 返回空结果、无效 JSON 或超出上限，**当**整理失败，**则不创建任何部分知识，
   用户可以重试。
5. **假设**用户发现页面内容不完整，**当**改用“截图”入口粘贴剪贴板图片，
   **则**系统继续使用现有附件安全门禁，不降级为网页抓取。

---

### 用户故事 3 - 安全、可部署和可审计（优先级：P1）

运维人员可以验证浏览器、OCR、AI 与回滚配置，原应用继续零影响运行。

**为何设置此优先级**：该链路依赖浏览器、OCR 和外部 AI，必须能在生产主机上独立验证。

**独立测试**：在 Ubuntu 部署环境安装 Chromium、Tesseract 中文语言包和 worker，完成一次
真实公开页面导入，并复核 `/`、`/app`、`/bank`、`/login` 不受影响。

**验收场景**：

1. **假设**部署缺少 `tesseract`、`chi_sim`、`eng`、worker jar 或浏览器目录，
   **当**执行部署，**则**在切换 release 前失败并指出缺失依赖。
2. **假设**部署切换到新 release，**当**执行公开检查，**则** `/kb` 与原拾题入口均可用。
3. **假设**新 release 健康检查失败，**当**部署回滚，**则**恢复上一 release 和 Nginx 配置。

### 边界情况

- URL 长度上限为 2,048 字符；移除片段标识；拒绝内嵌用户名或密码。
- 初始 URL 和最终 URL 都必须解析为公开地址。
- 页面加载最多 25 秒；worker 进程超时默认 35 秒；OCR 默认 30 秒。
- 截图最长 12,000 像素，临时文件最大 50 MiB，OCR 文本最多 30,000 字符。
- 单页最多生成 20 条知识；标题、正文、摘要、分类和标签均设长度上限。
- 重复标题在同一次 AI 结果中去重；空正文或只有 URL 的条目被丢弃。
- 截图、OCR 文本和 AI 原始响应不得写入日志；临时截图和最终 URL 元数据在请求结束后删除。
- 页面中的提示注入文本只作为待整理数据，不得改变系统指令、调用工具或读取本机资源。
- 相同 URL 重复提交不承诺自动去重；用户可通过普通知识去重流程处理重复结果。

## 需求（必需）

### 功能需求

- **FR-001**：网页链接入口必须执行“单页截图 -> OCR -> AI 拆分 -> 多条知识入库”流程。
- **FR-002**：系统必须只打开用户提交的一个 URL，不得跟随正文链接、遍历站点或分页采集。
- **FR-003**：系统必须只分析截图中的可见文字，不得把 URL、页面标题或来源地址充当正文。
- **FR-004**：系统必须允许 AI 把一个页面整理为 1–20 条知识，并过滤空标题、空正文和重复标题。
- **FR-005**：每条知识必须包含非空正文、标题，以及可用的摘要、分类和自动标签。
- **FR-006**：每条知识必须保留用户提交的原始 URL 和同一次采集时间。
- **FR-007**：系统必须在渲染前拒绝含凭据、非 HTTP/HTTPS、本机、私网和链路本地 URL。
- **FR-008**：浏览器 worker 必须拒绝指向非公开地址的 HTTP/HTTPS 子请求，并回传最终 URL。
- **FR-009**：后端必须重新校验最终 URL，不得信任浏览器回传值。
- **FR-010**：截图、OCR 或 AI 失败时不得创建部分知识或 URL-only 占位知识。
- **FR-011**：截图或 OCR 失败必须提示用户改用“截图”入口粘贴可见页面截图。
- **FR-012**：AI 返回必须经过 JSON 结构、字段类型、长度、条数和正文非空校验。
- **FR-013**：新增知识必须在同一事务内完成多条记录创建；任一条写入失败时全部回滚。
- **FR-014**：网页入口不得显示个人备注输入框，避免用户误以为备注会被保存。
- **FR-015**：网页入口必须显示处理中状态，并在成功后进入知识库，失败时保留 URL 供重试。
- **FR-016**：中文和英文界面必须完整覆盖入口、提示、执行中、无文字、整理失败和服务不可用。
- **FR-017**：功能必须适配桌面与 320–430 CSS 像素移动浏览器。
- **FR-018**：DeepSeek API Key 只能从环境变量读取，不得进入前端、日志、错误响应或仓库。
- **FR-019**：部署必须安装 Chromium、Tesseract `chi_sim+eng`、worker jar 并配置浏览器目录。
- **FR-020**：网页导入不得修改原拾题应用的进程、数据库、Cookie、支付或 Nginx 路由。
- **FR-021**：用户在提交网页导入前必须明确同意将本页 OCR 文本发送给 DeepSeek；未同意时
  不得启动浏览器捕获或外部 AI 调用。
- **FR-022**：OCR 文本必须在外部发送前扫描常见 API Key、Bearer Token、密码赋值和私钥；
  高置信度秘密必须替换为标记，知识备注必须说明发生过安全处理。
- **FR-023**：成功由网页 AI 整理的知识必须记录为 `succeeded` 处理状态，不得继续显示
  “未整理”。
- **FR-024**：发送给 DeepSeek 的内容只能包含脱敏后的截图 OCR 文本；原始 URL、最终 URL、
  查询参数、Cookie 和来源元数据不得进入外部 AI 请求。

### 关键实体

- **网页采集输入**：用户提交的公开 URL；只允许单页。
- **临时截图**：Playwright 渲染得到的 PNG；仅用于 OCR，不持久化。
- **临时最终 URL**：浏览器重定向后的地址；只在内存和临时文件中短暂存在，用于二次安全校验。
- **页面可见文本**：Tesseract 从截图识别出的文本；作为不可信输入发送给 AI。
- **整理知识**：AI 返回的单条候选知识，包含标题、正文、摘要、分类和标签。
- **知识条目**：最终持久化记录；正文为整理后文本，来源类型为 `webpage`，来源 URL 为原始 URL。

## 成功标准（必需）

### 可衡量结果

- **SC-001**：在 100 次受测网页导入中，创建 URL-only 知识的次数为 0。
- **SC-002**：在 100 次受测网页导入中，系统跟随正文链接、分页或站内导航的次数为 0。
- **SC-003**：在 100 次成功的多主题页面导入中，至少 90% 生成两条或以上有效知识。
- **SC-004**：在 100 次成功的网页导入中，原始 URL 和采集时间保留率为 100%。
- **SC-005**：私网、本机、凭据 URL 和重定向到私网的请求全部被拒绝，成功外发次数为 0。
- **SC-006**：AI 空结果、无效 JSON、超时和 OCR 无文字场景中，部分知识或占位知识写入次数为 0。
- **SC-007**：中文和英文的网页入口、执行中、成功、空文本、整理失败和不可用状态无缺失文案。
- **SC-008**：部署预检能够发现缺失的 Tesseract、中文语言包、worker 或 Chromium 目录。
- **SC-009**：未明确同意的网页导入在浏览器捕获和外部 AI 调用前被拒绝，外发次数为 0。
- **SC-010**：在 100 组包含常见 API Key、Token、密码和私钥的 OCR 样本中，原始秘密发送给
  DeepSeek 的次数为 0。

## 假设

- 用户只提交无需登录即可访问的公开页面。
- 用户有权处理页面中的可见内容，并理解页面文字会发送给已配置的 DeepSeek 服务。
- P0/P1 采用同步请求；部署 Nginx 读取超时为 120 秒，足以覆盖正常截图、OCR 和 AI 处理。
- 截图只作为 OCR 的临时输入，不作为附件持久化；来源追溯依赖 URL、时间和整理正文。
- AI 生成的分类和标签在 MVP 中写入知识备注文本；后续可迁移到独立标签与分类表。
- 现有截图与文档入口继续遵守附件扫描、密钥脱敏和失败关闭规则。
- 生产发布仍须执行真实公开 URL、原应用零影响和回滚验收。
