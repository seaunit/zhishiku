# 研究报告：网页截图 AI 拆分导入

## 1. 网页内容获取方式

**决策**：只渲染用户明确提交的一个 URL，并截图后 OCR。

**理由**：需求明确要求“AI 帮截图拆分整理”，且项目宪法禁止爬虫。单页截图能限制请求范围，
避免批量抓取、跟随链接和分页，也便于对浏览器网络请求执行公开地址检查。

**未采用方案**：

- 直接下载 HTML：无法满足“截图分析”语义，且易扩张为 DOM 爬取。
- DeepSeek Fetch 抓取任意正文：适合互联网候选的单 URL 获取，但不能替代本次网页入口的
  截图、OCR 和多知识拆分流程。
- 站内遍历或分页：违反单页边界和禁止爬虫原则。

## 2. 浏览器隔离

**决策**：使用独立 Playwright Java worker jar，由 Spring Boot 以受控子进程调用。

**理由**：Chromium 崩溃、内存峰值和浏览器依赖不会直接拖垮 API；worker 没有公共端口；
部署脚本可独立安装和验证 Chromium。worker 通过 1440×1200 视口捕获首屏及向下最长 12,000
像素的页面，不滚动触发懒加载，不点击任何元素。

**未采用方案**：

- 在 Spring Boot Web 进程内创建浏览器：生命周期和内存边界不清晰。
- 常驻浏览器池：MVP 并发低，增加进程管理复杂度。
- 浏览器微服务开放 HTTP：扩大攻击面和运维端口。

## 3. OCR

**决策**：使用 Tesseract CLI 从 PNG 读取 `chi_sim+eng`，标准输出最多 128 KiB，进入 AI
前最多保留 30,000 字符。

**理由**：安装简单、资源可控、符合现有 Ubuntu 部署；纯文本作为 AI 输入，避免把原始
截图或 OCR 文件持久化。文本不足 80 字符时拒绝，不生成空知识。

**未采用方案**：

- 云端 OCR：增加供应商、密钥和隐私授权范围。
- 直接让多模态模型读取截图：当前 DeepSeek Chat 配置为文本 JSON 整理，未建立独立视觉
  计费和隐私契约。
- OCR 结果全文落库：扩大敏感数据存储面，且需求只要求知识正文。

## 4. AI 整理和原子入库

**决策**：DeepSeek 返回固定 JSON `items` 数组，1–20 条；后端校验后将所有正文、摘要、
分类和标签在同一 Spring 事务中创建为知识。

**理由**：网页往往包含多个独立主题；一次页面采集可产生多条知识，符合“自动归类”目标。
整页先整理、后统一写入，可防止 AI 半成功时留下不完整知识集合。正文只来自 AI 整理结果，
URL 只进入来源。

**未采用方案**：

- 保存一个 URL 条目再异步整理：用户已明确否定 URL-only 行为。
- 为每个 AI 条目单独提交事务：部分失败会产生半套知识。
- 直接把 AI 返回 HTML 写入富文本：扩大脚本和危险链接风险。

## 5. URL 与网络边界

**决策**：初始 URL 在 Spring 中清理并校验；worker 对每个 HTTP/HTTPS 请求解析主机并拒绝
本机、私网、链路本地和多播地址；worker 返回最终 URL，后端再次清理、解析和校验。

**理由**：单页请求仍可能重定向或引用私网资源。双重校验降低 SSRF 和重定向绕过风险。

URL 只用于浏览器导航和来源追溯，不随 OCR 文本发送给 DeepSeek。签名参数、OAuth 回调参数
或其他查询凭据不得进入外部 AI 请求。

**未采用方案**：

- 只检查初始 URL：无法处理重定向和子资源。
- 只检查最终 URL：请求已经可能到达私网。
- 依赖域名黑名单：无法覆盖任意解析到私网的域名。

**剩余风险**：DNS 重绑定无法仅靠两次解析完全消除，生产可在网络策略层限制 worker
访问私网，并继续监控异常网络。

## 6. 失败处理

**决策**：截图、OCR、AI、JSON 校验和数据库事务任一失败都返回明确错误；不创建知识、
不把 URL 作为正文、不自动降级为 HTML 抓取。

**理由**：URL-only 与部分写入都会破坏用户对知识库准确性和可追溯性的信任。用户可重试，
或在“截图”入口主动粘贴有权查看的页面截图。

## 7. 外部 AI 同意与秘密处理

**决策**：每次网页导入要求用户明确勾选外部 AI 处理同意；OCR 文本在发送前扫描常见 API
Key、Bearer Token、密码赋值和私钥并替换为 `[REDACTED]`。

**理由**：网页可能包含用户未注意的访问凭据或私密内容。截图 OCR 后直接发送给第三方会扩大
泄露面。逐次明确同意避免把设置页中的本地偏好误当成服务端授权；发送前脱敏提供最后一道边界。

**未采用方案**：

- 默认直接外发：违反项目隐私门禁。
- 只依赖浏览器本地开关：服务端无法验证请求是否获得同意。
- 检测到可疑文本就保存原值：违反“不持久化秘密”的要求。

## 8. 分类与标签

**决策**：MVP 将 AI 分类和标签写入现有知识备注的安全文本字段。

**理由**：复用当前知识模型，快速交付网页整理 MVP，不新增迁移和关系表。

**后续**：分类与标签需要独立词表、锁字段、置信度和标签归一时，再建立版本化迁移；网页导入
接口无需改变。

## 9. 部署与可观测性

**决策**：部署安装 `tesseract-ocr`、`tesseract-ocr-chi-sim` 和 Playwright Chromium；
systemd 设置 `PLAYWRIGHT_BROWSERS_PATH=/opt/zhishiku/playwright`；API 通过子进程超时控制
worker 与 OCR。

**理由**：依赖缺失必须在切换 release 前失败。日志只记录错误类别和请求 ID，不记录 URL
凭据、OCR 文本、截图、AI 提示词或原始响应。
