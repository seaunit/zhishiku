# 功能规格说明：管理员账号管理台

**功能分支**：`011-admin-console`

**创建日期**：2026-10-26

**状态**：已实现并通过本地测试，待发布

**输入**：开发管理员页，只有管理员账号 `a115846` 才能访问。管理员可以查看用户账号信息，包括
点数消耗情况；可以启用或禁用普通用户账号；可以向指定账号赠送点数。

## 用户场景与测试 *（必需）*

### 用户故事 1 - 仅管理员查看账号列表和点数概况（优先级：P1）

管理员登录识海后，可以从侧栏进入“账号管理”，搜索并分页浏览账号。列表显示账号身份、启用状态、
注册时间、当前可用点数、已预留点数和累计消耗点数；管理员还能查看账号详情摘要。

**为何设置此优先级**：管理员首先要能准确找到账号并理解其状态和点数使用情况，后续管理动作才有
可靠依据。

**独立测试**：分别使用未登录会话、普通账号和管理员账号请求管理接口；只有管理员账号能够取得
账号列表和详情，其他请求不得返回任何账号数据。

**验收场景**：

1. **假设**管理员账号 `a115846` 已启用并已用正确密码和图形验证码登录，**当**管理员打开账号
   管理页，**则**页面显示分页账号列表和真实点数概况。
2. **假设**普通用户已登录，**当**该用户直接访问管理页或管理接口，**则**系统返回拒绝访问，
   且不泄露账号数量、邮箱、点数或账号标识。
3. **假设**管理员输入邮箱、显示名称或账号名称的一部分，**当**执行搜索，**则**列表只返回
   匹配账号，并保留分页总数。
4. **假设**账号尚无点数账户或消费记录，**当**管理员查看该账号，**则**点数显示真实的 `0`，
   不得用空值或虚构数据替代。

---

### 用户故事 2 - 管理员启用或禁用普通账号（优先级：P1）

管理员可以禁用指定普通账号，使其不能继续登录，并要求已有会话在后续请求时失效；也可以重新启用
账号。管理员账号本身不得被禁用。

**为何设置此优先级**：账号停用是控制滥用和异常访问的必要能力，必须立即阻止旧会话继续使用。

**独立测试**：禁用账号后验证新登录被拒绝、旧会话请求被拒绝；重新启用后验证登录和原账号数据恢复，
并核对每次状态变更都有管理员、时间、原因和前后状态记录。

**验收场景**：

1. **假设**管理员查看一个启用中的普通账号，**当**管理员确认禁用并提供原因，**则**账号变为
   禁用，后续登录被拒绝，已有会话失效。
2. **假设**普通账号已被禁用，**当**管理员确认启用并提供原因，**则**账号恢复可用，原账号的
   知识、点数和历史数据不受影响。
3. **假设**管理员尝试禁用管理员账号或自身账号，**当**提交请求，**则**系统拒绝操作并保持原状态。
4. **假设**同一个停用请求因网络重试被重复提交，**当**服务端收到相同幂等请求，**则**只产生一次
   状态变更和一条审计记录。

---

### 用户故事 3 - 管理员向指定账号赠送点数（优先级：P2）

管理员可以向一个普通账号赠送正整数点数，必须填写原因。赠送通过点数批次和只追加账本完成，
账号可用余额、累计发放、明细和当前页面同步更新。

**为何设置此优先级**：赠送点数服务于补偿和运营，但必须可审计、可追溯，不能直接修改余额。

**独立测试**：给指定账号赠送点数后核对余额、批次、账本、原因和管理员身份；重放同一请求不得重复
到账；非法点数、未知账号和停用账号不得被错误操作。

**验收场景**：

1. **假设**管理员选中一个普通账号，**当**输入 1–100,000 范围内的整数点数、原因并确认，**则**
   点数通过 `manual_adjustment` 批次到账，账本记录赠送原因和管理员审计关联。
2. **假设**管理员输入 0、负数、非整数或超过上限的点数，**当**提交，**则**系统阻止赠送且余额不变。
3. **假设**同一赠送请求被重复提交，**当**服务端识别到相同幂等键和请求体，**则**返回首次结果且
   不重复加点。
4. **假设**管理员向管理员账号或不存在账号赠送，**当**提交，**则**系统拒绝操作，不创建批次或账本。
5. **假设**赠送成功，**当**管理员回到账号列表，**则**该账号的可用点数、累计发放和最近操作状态
   立即反映新结果。

---

### 用户故事 4 - 管理页中英双语与移动端可用（优先级：P3）

管理页默认中文，可切换英文；桌面和手机均可完成搜索、分页、状态切换和点数赠送。所有破坏性操作
必须二次确认，并清楚说明影响。

**为何设置此优先级**：管理能力必须与产品整体双语和移动访问约束一致，但不应牺牲权限和账务正确性。

**独立测试**：在 1440、768、390 CSS 像素宽度下检查主要流程，切换中英文，使用键盘完成确认和取消，
并验证错误提示位于对应操作附近。

**验收场景**：

1. **假设**浏览器语言偏好为中文，**当**管理员打开管理页，**则**所有标题、字段、状态、确认文案和
   错误提示默认显示中文。
2. **假设**管理员切换英文，**当**检查账号、点数、停用、启用和赠送文案，**则**事实和数值与中文
   版本一致。
3. **假设**管理员使用手机访问，**当**浏览账号列表并打开行操作，**则**表格转为可读的两行账号项，
   页面不横向溢出，触控目标不少于 44 像素。

### 边界情况

- 管理员账号密码只能通过环境变量或受管密钥服务注入；仓库、文档、日志、错误消息和审计记录不得
  保存明文密码。
- 管理员用户名固定为 `a115846`，即使普通用户拥有相同显示名称也不得获得管理员权限。
- 管理员登录仍必须通过一次性图形验证码；账号被禁用时不得通过密码校验继续登录。
- 权限判断必须以认证会话解析出的数据库账号身份、角色和用户名为准，不能信任前端隐藏菜单或提交
  参数。
- 管理员会话过期、CSRF 校验失败或被降权时，管理接口必须拒绝请求。
- 管理列表不得显示密码哈希、会话标识、密钥、支付签名或不相关账号的聊天和知识正文。
- 账号搜索词、分页游标和赠送原因必须限制长度并进行安全输出编码。
- 账号列表为空、搜索无结果、加载中、请求失败和刷新时保持页面结构稳定，并提供明确状态。
- 停用账号时必须保持知识、附件、订单、退款和账本数据完整，不得删除或回收已购点数。
- 盘点点数时，累计消耗以账本结算事实为准；不得把预留点数误算为已消耗。
- 赠送点数失败时必须在同一事务中回滚批次、账户投影和账本，不得出现部分到账。
- 管理员不能修改角色、注册邮箱、密码或其他未在本次范围内的字段。

## 需求 *（必需）*

### 功能需求

- **FR-001**：系统必须只允许用户名 `a115846`、角色为管理员且状态为启用的账号访问管理页和全部
  管理接口。
- **FR-002**：管理员密码必须通过 `SHIHAI_ADMIN_PASSWORD` 或受管密钥服务在首次初始化时注入，
  数据库只保存强密码哈希；不得在源码、SDD 文档、前端构建或日志中出现明文。
- **FR-003**：管理员必须使用现有图形验证码登录流程；登录标识输入框必须兼容普通用户邮箱和
  管理员用户名。
- **FR-004**：系统必须保存账号角色、用户名和启用状态；普通注册账号默认为普通用户和启用状态。
- **FR-005**：管理接口必须提供按邮箱、显示名称或用户名搜索的分页账号列表，并返回账号 ID、
  登录标识、显示名称、角色、状态、注册时间、可用点数、预留点数、累计发放和累计消耗。
- **FR-006**：管理接口必须提供单个账号详情，返回与列表一致的真实点数汇总，不返回密码哈希和
  会话信息。
- **FR-007**：管理员必须能够填写原因后启用或禁用普通账号；管理员账号不得被禁用。
- **FR-008**：账号被禁用后必须立即阻止新登录，并在已有会话的下一次受保护请求中使会话失效。
- **FR-009**：状态变更必须记录操作管理员、目标账号、原因、前后状态和时间，且相同幂等请求不得
  重复应用。
- **FR-010**：管理员必须能够向普通账号赠送 1–100,000 点，必须填写原因和稳定幂等键。
- **FR-011**：赠送点数必须创建 `manual_adjustment` 点数批次、更新点数账户投影并追加账本，
  三步处于同一数据库事务。
- **FR-012**：赠送成功后必须返回最新账号摘要，前端必须更新列表和详情中的可用点数、累计发放。
- **FR-013**：所有管理写操作必须受 CSRF、幂等和会话权限保护；跨账号管理必须由服务端完成。
- **FR-014**：管理页必须默认中文并支持英文，桌面和移动端完成主要流程，错误状态与确认状态可访问。
- **FR-015**：`/api/v1/admin/billing/**` 等既有管理接口必须继续认可配置的计费管理员，同时不得
  向普通账号开放。

### 关键实体

- **账号（Owner Account）**：识海用户身份，包含邮箱、可选用户名、显示名称、角色、启用状态、
  密码哈希和注册时间。
- **点数账户（Credit Account）**：账号的可用、预留、体验、购买、累计发放和累计消耗投影。
- **点数批次（Credit Batch）**：赠送或购买产生的一批点数，记录剩余量、来源和优先级。
- **账本明细（Ledger Entry）**：只追加的点数事实，记录变化量、业务引用、安全描述和发生时间。
- **管理审计（Admin Audit）**：记录管理员对账号状态和点数执行的敏感操作、幂等键、原因和结果。

## 成功标准 *（必需）*

### 可测量结果

- **SC-001**：100% 的未登录、普通用户和已禁用管理员请求都无法取得管理账号数据。
- **SC-002**：管理员可在 30 秒内通过搜索找到目标账号，并看到其状态和点数概况。
- **SC-003**：账号停用成功后，新登录和旧会话在下一次请求中均被拒绝，成功率达到 100%。
- **SC-004**：赠送点数成功时，账户余额增加量、账本变化量和返回摘要完全一致，误差为 0。
- **SC-005**：同一幂等请求重放 10 次，只会产生 1 次状态变更、1 次赠送和 1 条对应账本。
- **SC-006**：管理页在 1440、768 和 390 CSS 像素宽度下无横向页面溢出，核心操作均可完成。
- **SC-007**：中文和英文界面中的账号状态、点数值和错误事实保持一致，关键文案覆盖率 100%。

## 假设

- 现有邮箱密码登录、图形验证码、Spring Security 会话、点数批次和账本结构继续复用。
- 管理员账号与本项目其他账号使用同一会话体系，但由独立角色和固定用户名限制权限。
- 管理员初始密码由部署过程交互输入并只写入该部署环境的密钥配置；普通重新部署留空时保留原密码。
- 本次不提供账号删除、角色编辑、密码重置、退款或跨账号数据查看。
- 停用账号只阻止访问，不改变数据保留、订单或点数所有权。
- 管理列表默认每页 20 条，搜索和审计保留策略沿用项目现有运行与数据保留约束。
