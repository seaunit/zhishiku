# 技术研究：管理员账号管理台

## 决策 1：管理员使用现有账号体系并增加角色

**决策**：在 `owner_account` 增加可选唯一用户名 `username`、角色 `account_role` 和状态
`account_status`。管理员用户名固定为 `a115846`，角色为 `ADMIN`，普通注册账号为 `USER`。

**理由**：复用现有邮箱密码、BCrypt、Spring Security、图形验证码和 Spring Session，不建立第二套
认证 cookie。登录输入兼容邮箱和用户名，可以最小改动满足管理员登录。

**备选方案**：

- 独立管理员表和独立登录：隔离更强，但需要第二套会话、CSRF、过滤器和管理密码流程，MVP 复杂度高。
- 通过配置邮箱判断管理员：已有计费管理支持邮件列表，但无法满足固定用户名，也没有普通账号停用能力。

## 决策 2：角色与用户名双重校验

**决策**：管理授权同时要求当前数据库账号已启用、角色为 `ADMIN`、用户名等于配置的管理员用户名。

**理由**：避免仅靠显示名称或邮箱本地部分被冒用，也避免普通账号被错误提升后访问管理页。

**备选方案**：只检查角色。角色一旦被错误修改就扩大权限面，不满足“只有 a115846”这一明确约束。

## 决策 3：管理员密码通过首次初始化写入哈希

**决策**：新增 `SHIHAI_ADMIN_USERNAME` 和 `SHIHAI_ADMIN_PASSWORD`。启动时仅在管理员账号不存在时
使用密码创建账号；已存在时保留现有哈希。运维可以显式使用受管脚本轮换密码，但不在普通重部署时
自动重置。

**理由**：避免每次部署因空输入或自动生成密码改变管理员凭据，也避免把明文写入数据库、日志、
systemd 配置或仓库。密码只出现在首次部署的受保护环境文件/受管密钥中，数据库保存 BCrypt。

**备选方案**：硬编码密码或仓库内默认密码被明确禁止。

## 决策 4：会话状态过滤器使禁用立即生效

**决策**：在 Spring Security 过滤器链增加轻量 `OncePerRequestFilter`。对已认证请求解析当前账号，
若状态不是启用则清空安全上下文和会话并返回 401。

**理由**：`UserDetails.isEnabled()` 只能阻止新登录，无法撤销已有持久化会话。每次已认证请求读取账号
状态是当前单体规模下最简单可靠的失效方式。

**备选方案**：遍历并删除 Spring Session。Spring Session JDBC 没有稳定、低成本的按 principal 批量
失效 API，且并发新增会话仍可能竞态。

## 决策 5：用户管理接口由独立服务聚合数据

**决策**：

- `GET /api/v1/admin/users` 使用 `JdbcTemplate` 做分页和搜索。
- 账号表与 `billing_credit_account` 左连接，无点数账户返回真实 0。
- 知识数量使用按 owner 聚合的子查询，读取 `knowledge_item` 计数，不读取正文。
- `PATCH /api/v1/admin/users/{ownerId}/status` 更新账号状态并写审计。
- `POST /api/v1/admin/users/{ownerId}/point-grants` 调用现有 `BillingService.manualAdjustment`。

**理由**：聚合查询可控且避免加载无界实体；点数赠送继续走既有事务和账本不变量。

## 决策 6：管理写操作使用持久化幂等键

**决策**：复用 `IdempotencyService`。状态修改和赠送点数均要求 16–128 字符 `Idempotency-Key`，
请求哈希覆盖目标账号、动作、原因和点数。

**理由**：网络重试、用户双击或网关重放不得重复停用或赠送。

## 决策 7：管理页视觉方向使用 Framed sheet

**决策**：Taste 方向 seed `619440299`，样式 `framed-sheet`。使用现有深海品牌色作为低彩度框体，
内容置于浅色工作面板；账号表不带卡片外壳，搜索和操作在标题行下方。

**理由**：这是管理工作台，核心是快速扫描账号、状态和点数，不是营销页面。现有品牌固定调色板与
Public Sans，保留配色和字体，只采用该方向的信息层级、间距和表格结构。

**“Its face”**：框体使用识海深海蓝的低彩度混合色，点数数据使用品牌青色作为唯一主数据色。

**签名元素**：账号行中的“点数轨迹”，用可用、冻结、累计消耗三个对齐数值表达账号的使用状态，
替代通用 KPI 图标卡。

## 决策 8：不新增依赖

**决策**：分页、搜索、CSRF、幂等、审计和视觉实现全部复用现有栈和组件。

**理由**：本次能力不要求新的运行时库，新增依赖会增加供应链和部署风险。
