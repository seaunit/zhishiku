# 阶段 0 研究：识海富文本知识编辑

**功能**：`004-rich-text-editor`

**日期**：2026-10-21

## 决策 1：使用受限语义文档，不保存任意 HTML

**决策**：正文权威格式为版本化的结构化文档。编辑器、粘贴转换器、服务端校验器和详情渲染器
共享同一节点和标记集合。

**理由**：直接保存 HTML 会把 XSS、事件属性、远程资源、样式漂移和不可控插件带入知识库。
结构化文档能对节点、属性和嵌套深度做确定性验证，也能稳定生成纯文本投影。

**替代方案**：

- 只保存 HTML：实现快，但安全清洗、迁移和搜索一致性风险高，不采用。
- 只保存 Markdown：适合技术文本，但图片、表格、Word 粘贴和富文本详情体验不足。
- 同时维护 HTML 和 Markdown 双权威：同步和迁移复杂，不采用。

## 决策 2：编辑器采用 Tiptap/ProseMirror

**决策**：Web 编辑器使用 Tiptap/ProseMirror；服务端复用 ProseMirror schema 校验。

**理由**：其文档模型天然适合白名单、节点转换、撤销、粘贴和表格扩展；比
`contenteditable + execCommand` 更可测试、可持续维护。

**替代方案**：

- 原生 `contenteditable`：原型可用，但生产环境跨浏览器和 schema 校验成本高。
- iframe 中嵌入第三方 Word 编辑器：依赖重、样式和安全边界不可控，不采用。
- Markdown 编辑器：不符合类似 Word 的富文本需求。

## 决策 3：正文结构化文档与纯文本投影同事务更新

**决策**：保存时的同一事务写入结构化正文、schema 版本、派生纯文本、图片引用和搜索修订号。

**理由**：搜索和 AI 不得读到旧正文；正文与投影分离后，Meilisearch 仍可作为可重建派生索引。

**替代方案**：异步单独生成投影会产生一段时间的不一致，不作为默认。

## 决策 4：内嵌图片使用稳定附件引用

**决策**：正文图片节点保存附件 ID、说明、替代文本、显示宽度和对齐，不保存远程 URL 或 HTML
字符串。实际图片地址在读取时按权限生成。

**理由**：可复用 001 的安全扫描、脱敏、生命周期和孤儿清理；正文移动或修改说明不会复制图片。

**替代方案**：

- Base64 放进 JSON：正文膨胀、重复存储、无法单独清理，不采用。
- 只保存远程 URL：追踪、失效、隐私和存储风险，不采用。

## 决策 5：图片安全采用整次保存失败

**决策**：任一待保存图片无法完整扫描或可靠脱敏时，本次知识保存整体失败，不写入文档版本、
图片引用或附件提升。未提交内容保留在当前编辑器或安全草稿中。

**理由**：与 001 的“未扫描附件不得持久化”规则一致；部分保存会产生无法审计的半安全正文。

**替代方案**：跳过失败图片只保存其余内容，会让用户误以为全部内容已保存，不采用。

## 决策 6：外部粘贴先转换为内部 schema

**决策**：Word、Google Docs 和网页 HTML 先经过允许列表转换，再进入编辑器；脚本、事件属性、
表单、iframe、样式表、跟踪像素和危险链接被移除。支持“粘贴为纯文本”回退。

**理由**：浏览器剪贴板中的 HTML 不可信；只保留对知识阅读有意义的语义格式。

**替代方案**：原样粘贴后渲染时再清洗，会留下恶意内容进入数据库和索引的窗口，不采用。

## 决策 7：远程和本地伪协议图片不自动加载

**决策**：粘贴内容中的远程、`data:`、`blob:`、`cid:`、`file:` 和 SVG 图片不成为正文图片
节点；保留安全占位或普通来源链接，用户主动上传后才生成附件引用。

**理由**：防止跟踪请求、数据 URI 膨胀和脚本化图片。详情页只能加载系统内已验证附件。

## 决策 8：详情从结构化文档安全渲染

**决策**：详情由客户端/服务端共享 schema 生成只读视图，不能直接插入用户 HTML。

**理由**：详情页是另一个高风险渲染面；只读不等于安全。图片必须通过附件解析器加载。

## 决策 9：搜索与 AI 使用派生纯文本

**决策**：投影包含段落、标题、列表、引用、表格、代码、图片说明和替代文本；不含标签名、
附件存储键、脚本或隐藏样式。

**理由**：用户应当通过看到的文字和图片描述找到知识；AI 不应接收可执行标记。

**图片计费**：默认文本分析不自动分析图片。用户明确选择图片 OCR/vision 时，每张唯一图片按
002 的 10 点计费；正文重复引用同一附件只计一次。004 先提交去重后的 `imageAssetIds`，002
在服务端解析安全资产并按规范化图片内容哈希去重，报价响应返回唯一资源清单。

## 决策 10：图片配额与预处理

**决策**：

- 每条知识最多 20 张内嵌图片。
- 单个源文件不超过 25 MiB；处理后图片合计不超过 50 MiB。
- 每边最大 8192 像素、总解码像素不超过 4000 万。
- 支持 JPEG、PNG、WebP 和受支持 iOS 浏览器提供的 HEIC/HEIF。
- 处理时修正方向、移除不必要 EXIF/XMP，并将动画图片静态化或拒绝。

**理由**：控制数据库引用、对象存储、解码内存和移动上传体验。

## 决策 11：富文本版本和冲突处理使用显式出口

**决策**：保存带 `expectedVersion`，冲突时不静默覆盖；用户可重新加载最新版本、将本地版本另存
为新知识，或查看差异后明确覆盖。

**理由**：移动端和双标签页编辑增加并发概率，丢失内容的代价高于多一次选择。

## 决策 12：旧纯文本幂等迁移

**决策**：旧 `body` 文本按段落和换行转换为默认段落/硬换行，生成结构化文档和纯文本投影。
迁移使用内容哈希和版本条件更新，可重复执行。

**理由**：不能让一次失败或并发打开导致重复转换、换行丢失或重复图片引用。

## 决策 13：图片引用清理与知识生命周期一致

**决策**：文档删除图片节点后，引用进入待清理状态；只有没有任何 active/回收站保留引用的附件
才能按现有对象生命周期删除。附件仍与知识条目回收站和永久清除规则一致。

**理由**：避免正文编辑误删来源附件或共享图片，同时防止长期孤儿资源。

## 决策 14：移动端和无障碍复用现有 App Screen 规则

**决策**：工具栏是 neutral control bar，不引入新卡片或悬浮球；主要操作 44×44 CSS 像素，
其余格式进入更多菜单，菜单打开时保留选区；表格支持表头、行列语义和局内滚动。

**理由**：移动端编辑器必须像工作工具，而不是缩小版 Word 工具栏。

## 决策 15：来源和转换过程独立留痕

**决策**：粘贴、网页、文档和旧文本转换在 `rich_document_source` 中记录来源类型、清理后的
HTTP/HTTPS URL、采集时间、转换时间、converter version、安全内容哈希；格式变化写入独立
转换报告。正文不保存 Cookie、Authorization、完整剪贴板、原始 HTML 或含凭据 URL。

**理由**：用户需要知道内容来自哪里、何时转换以及哪些格式被移除；将来源混入正文会增加泄漏
面和 schema 复杂度。独立记录也便于迁移重试、审计和后续 converter 升级。

**替代方案**：只在正文 attrs 中保存来源会污染内容语义，并可能把敏感请求头或完整剪贴板带入
持久化文档；仅写日志无法支持用户复核和数据库级一致性，不采用。

## 已解决的未知项

- 正文格式：结构化 ProseMirror 子集。
- 编辑器：Tiptap/ProseMirror。
- 图片：既有安全附件 ID 引用，无远程 URL/data URI。
- 投影：保存事务内生成纯文本。
- 粘贴：schema 转换 + 纯文本回退。
- 冲突：版本检查 + 三个用户出口。
- 旧数据：幂等迁移。
- 移动端：渐进工具栏和 44px 控件。
