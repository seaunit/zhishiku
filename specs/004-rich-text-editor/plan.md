# 实施计划：识海富文本知识编辑

**分支**：`004-rich-text-editor` | **日期**：2026-10-21 | **状态**：草案

**规格**：[spec.md](spec.md)

**上游功能**：[001 个人知识库](../001-ai-personal-knowledge-base/plan.md)、

## 摘要

把手动采集和知识编辑从纯文本框升级为受限、语义化富文本编辑器，支持正文图片、Word/Google
Docs/网页粘贴、富文本详情展示、派生纯文本搜索和 AI 输入。正文使用版本化结构化文档，不保存
可执行 HTML；图片继续经过 001 的附件扫描、密钥检测和脱敏门禁。前端采用 Tiptap/ProseMirror
编辑能力，服务端使用同一节点/标记白名单验证，详情从结构化文档安全渲染。

## 技术背景

**语言/版本**：Node.js 24 LTS、TypeScript 5.x、React 19、Next.js 16 App Router

**主要依赖**：Tiptap/ProseMirror、Zod、Drizzle ORM、Sharp、现有 S3 附件服务、
现有 OCR/密钥扫描器、next-intl、Radix UI primitives、Lucide icons、Playwright、Vitest

**存储**：PostgreSQL 保存结构化正文、内容摘要、版本和图片引用；S3 兼容私有对象存储保存
经过验证的图片资源；Meilisearch 保存派生纯文本和图片说明/替代文本

**测试**：Vitest、fast-check、Testcontainers、Playwright、axe-core、Schemathesis、
k6、Semgrep、Gitleaks、Trivy

**目标平台**：现有识海 Web 应用；桌面、平板和 320–430 CSS 像素手机浏览器

**项目类型**：Web 应用功能扩展，不新增独立服务或数据库

**性能目标**：200,000 字符和 20 张安全图片的条目在常规设备上保持可编辑；详情首屏不因图片
加载发生明显布局跳动；派生纯文本更新不阻塞手动保存

**约束**：禁止执行粘贴 HTML、脚本、表单、iframe 和远程图片；图片先扫描后保存；结构化文档
和纯文本投影必须同事务更新；旧纯文本条目安全迁移；移动端和无障碍规则继续生效

**规模/范围**：单所有者、最多 20 张内嵌图片/条、单图 25 MiB、处理后图片合计 50 MiB、
正文纯文字沿用 200,000 字符限制

## 架构决策

1. **结构化文档为唯一正文格式。**
   正文保存 ProseMirror JSON 的受限子集，并附带 schema 版本和派生纯文本。原始 HTML 只作为
   粘贴输入，不是持久化或详情渲染的权威格式。

2. **编辑器和服务器共享同一 schema。**
   Web 编辑器通过 Tiptap 节点/标记白名单生成文档；服务端使用 Zod + ProseMirror schema
   重新验证、规范化并重建派生文本，拒绝未知节点、危险属性和超限内容。

3. **图片保持为附件资源。**
   正文图片节点使用统一的 `assetId` 字段：编辑提交时为所有者级临时 `uploadId`，保存事务
   解析后持久化为正式 `attachmentId`；替代文本、说明、对齐、宽高比和显示尺寸随节点保存。
   图片 URL 只在读取时按权限安全生成，临时 ID 不得出现在已保存文档或公开响应中。

4. **外部图片请求失败关闭。**
   远程 `<img>`、`data:`、`blob:`、`cid:`、`file:` 和脚本化 SVG 不成为正文图片节点。
   粘贴时保留未解析占位或普通来源链接，用户主动上传后才形成安全内嵌图片。

5. **图片全次拒绝保存与编辑器保留分离。**
   任一图片扫描失败时，本次知识保存整体失败，不产生新知识版本或图片引用；未提交编辑内容
   保留在当前编辑器/安全草稿中，用户移除或替换后可重试。

6. **纯文本投影是搜索和 AI 边界。**
   保存时从可见正文、表格文字、代码、图片说明和替代文本生成纯文本。搜索索引和 AI 只使用
   该投影与明确授权的图片引用，不发送内部节点、脚本或存储键。

7. **富文本详情由结构化文档渲染。**
   详情使用同一 schema 生成只读视图，图片按稳定比例按需加载。不得把用户粘贴 HTML 直接
   插入 DOM。

8. **版本冲突可见且安全。**
   正文、纯文本投影和引用作为同一版本提交；双标签页冲突时提供重新加载、另存为新知识或
   明确覆盖，已上传图片由临时引用和孤儿清理任务处理。

9. **移动端编辑采用渐进工具栏。**
   常用格式保持 44×44 CSS 像素触控目标，其余格式进入“更多”菜单或横向工具栏；打开菜单时
   保留文本选区，软键盘、横屏和安全区不得遮挡正文。

10. **旧数据无损迁移。**
    纯文本按段落和换行转换为结构化文档；迁移幂等，可重试，不产生重复图片或丢失换行。

11. **来源与转换过程单独留痕。**
    粘贴、网页、文档和旧文本转换记录来源类型、清理后的 HTTP/HTTPS URL、采集时间、转换时间、
    converter version、安全内容哈希和格式保留/降级/移除报告。正文不保存 Cookie、
    Authorization、完整剪贴板、原始 HTML 或含凭据 URL。

12. **图片 AI 分析按唯一内容计费。**
    用户明确选择图片分析后，004 把去重后的 `imageAssetIds` 交给 002 报价；002 服务端解析
    同一所有者、已扫描的资产，并按规范化图片内容哈希返回唯一资源清单。同一图片在正文重复
    出现或具有多个引用位置时只计一次，失败步骤释放对应预留。

## 数据与接口

- 数据实体、约束、状态和迁移规则见 [data-model.md](data-model.md)。
- 结构化文档 Schema 见 [contracts/rich-text.schema.json](contracts/rich-text.schema.json)。
- 编辑器图片暂存接口见 [contracts/image-upload.openapi.yaml](contracts/image-upload.openapi.yaml)。
- 001 的知识条目响应增加结构化正文和派生纯文本版本；旧 `body` 保留为兼容投影。
- 列表和搜索结果使用不含完整 `bodyDocument` 的摘要 DTO；只有详情接口返回完整结构化正文。
- 旧条目迁移前返回 `bodyDocument=null` 和 `bodyMigrationState`，详情只读展示纯文本，迁移完成后
  才开放富文本编辑。
- 富文本编辑器提交结构化文档、版本号、图片引用和派生纯文本，服务端重新生成投影并验证。
- 图片上传使用独立的 004 暂存会话，并复用现有扫描、脱敏和对象存储安全管线；只有保存时
  才把 ready upload 提升为带 `item_id` 的正式附件。
- 创建或更新富文本时可选提交 `bodySource` 提示；服务端负责 URL 清理、来源记录、转换报告和
  converter version，客户端不能指定转换成功状态或绕过来源校验。
- `knowledge_item.version` 是唯一客户端乐观锁；`rich_document.version` 只做同事务镜像。
- 旧条目通过独立迁移状态表发现和重试，不依赖尚未创建的富文本文档行。

## 性能和可靠性

- 200,000 字符和 20 张图片不得造成输入明显卡顿；超出限制时在保存前阻止。
- 图片按需加载并使用固定宽高比占位，避免详情页布局跳动。
- 自动保存和手动保存均使用幂等和版本冲突检测。
- 保存事务同时更新结构化文档、纯文本投影、图片引用和搜索修订。
- 图片失败、附件孤儿和旧数据迁移均可重试，不丢失已输入文字。

## 测试策略

- 单元测试：节点/标记白名单、HTML 粘贴转换、纯文本投影、限制、幂等、版本冲突。
- 集成测试：结构化文档事务、图片扫描/提升/引用、搜索投影、旧数据迁移、孤儿清理。
- 契约测试：结构化文档 JSON Schema、拒绝未知节点、危险属性和超限输入。
- E2E：编辑、格式化、粘贴、图片插入、详情渲染、双标签页冲突和移动工具栏。
- 安全测试：脚本、事件属性、表单、iframe、远程/data/blob/file 图片、SVG 和提示注入。
- 视觉测试：`data-terminal` 风格保持，1440/768/390/360 使用 Taste 和真实浏览器。

## 实施顺序

### P0 — MVP 关键路径

1. 产品冻结格式范围、截图仅剪贴板、文档入口接收图片和无障碍边界。
2. 共享 schema、纯文本投影、安全验证器和转换来源记录。
3. PostgreSQL 文档、修订、图片引用、暂存上传、迁移状态和转换报告实体。
4. 编辑器基础格式、正文图片安全保存、详情安全渲染和手机基础布局。
5. 搜索/AI 纯文本投影、唯一图片报价、基础键盘与屏幕阅读器支持。
6. 任一图片失败即整次保存失败，编辑器保留未提交内容。

### P1 — 完整发布

1. Word/Google Docs/网页粘贴、纯文本回退和格式转换提示。
2. 表格编辑与窄屏局内滚动、图片高级操作和冲突处理。
3. 旧纯文本幂等迁移、回收站/永久删除和图片引用清理。
4. 完整移动工具栏、360/390/430、200% 字体、双语和零影响回归。
5. Taste、安全语料、性能、来源追踪和发布门禁。

### P2 — 持续加固

1. 浏览器刷新与进程重启恢复。
2. 可用性研究、模糊测试扩展和 schema 演进演练。
3. 图片保留、依赖升级、回滚和长期维护报告。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 粘贴 HTML XSS | 只接受结构化 schema；服务端重新验证；详情不渲染原始 HTML |
| 远程图片触发跟踪请求 | 非内部附件节点一律不渲染，保持占位或安全链接 |
| 图片扫描失败造成部分保存 | 整次保存失败，未提交编辑区保留内容 |
| 双标签页覆盖 | 版本条件更新、冲突出口和本地草稿 |
| 搜索索引与正文不一致 | 同事务更新纯文本与 search revision，派生索引重试 |
| 移动工具栏遮挡 | 44px 控件、更多菜单、软键盘和安全区真实浏览器验证 |
| 重复图片重复扣费 | 服务端按安全内容哈希去重，报价响应回传唯一资源清单，重复引用不增加数量 |
| 来源信息与正文混杂 | 正文只保存结构化文档，来源与转换报告写入独立实体，不信任客户端转换结果 |

## 复杂度跟踪

引入结构化文档和投影增加迁移与验证成本，但这是防止 XSS、远程图片请求、搜索脏数据和旧
正文不一致所必需。没有新增独立服务；继续复用 001 的附件、搜索、AI 和 003 的移动边界。
