# 快速入门与验证：识海富文本知识编辑

**功能**：`004-rich-text-editor`

**目的**：在实现完成后验证富文本编辑、图片插入、粘贴、详情渲染、搜索、AI、移动端和迁移。
本文是验收指南，不代表当前生产代码已实现。

## 前置条件

- 001、002、003 的本地 Web、Worker、PostgreSQL、Meilisearch 和对象存储已运行。
- 已应用富文本文档、修订和图片引用迁移。
- 浏览器支持 ClipboardEvent、文件选择和响应式布局。
- 测试图片、文档和恶意 HTML fixture 位于 `tests/fixtures/rich-text/`。

## 启动

```powershell
pnpm install
docker compose -f infra/compose.yml up -d
pnpm db:migrate
pnpm dev
```

打开 `http://localhost:3000/kb`。

## 验证场景

### 1. 基础富文本

1. 打开手动采集，输入标题和正文。
2. 使用标题、粗体、斜体、下划线、列表、引用、链接、代码和撤销/重做。
3. 保存并重新打开，确认格式和顺序一致。
4. 使用“清除格式”，确认文字保留。

### 2. 正文图片

1. 从本地选择 JPG、PNG 和 WebP 图片，分别插入正文。
2. 观察上传、扫描、成功、失败和重试状态。
3. 调整图片顺序、宽度、对齐，填写说明和替代文本。
4. 保存并重新打开，确认图片位置、说明和替代文本一致。
5. 尝试 HEIC/HEIF、动画图片、超大像素、SVG 和脚本化图片，确认规范化或拒绝。

### 3. 截图与文档入口边界

1. 打开截图入口，确认页面只有剪贴板粘贴区，没有文件选择、拖放、相册或相机控件。
2. 从剪贴板粘贴一张截图，确认预览、大小校验、扫描状态和保存路径正常。
3. 打开文档入口，分别选择 PDF/DOCX、JPG、PNG、WebP 和 HEIC/HEIF，确认文档与图片都进入相同安全检查，但图片不会自动写入正文。
4. 确认截图入口不能通过脚本触发的文件选择或拖放绕过剪贴板限制。

### 4. 密钥与全次拒绝

1. 插入一张可检测密钥的合成图片。
2. 确认只保留经过验证的脱敏派生图。
3. 插入一张无法完整扫描的图片并保存。
4. 确认本次保存整体失败、没有新文档版本；编辑器仍保留未提交文字和其他图片。
5. 移除或替换失败图片后重试，确认保存成功。

### 5. 外部粘贴与来源追踪

1. 从 Word、Google Docs 和网页粘贴包含标题、列表、链接和表格的内容。
2. 确认受支持语义保留、样式统一，脚本/iframe/表单被移除。
3. 粘贴远程、`data:`、`blob:`、`cid:`、`file:` 图片，确认不发起网络请求，只出现安全占位或来源链接。
4. 使用“粘贴为纯文本”，确认文字、换行和链接地址保留。
5. 查看来源与转换报告，确认来源类型、清理后的 URL、采集/转换时间、converter version、内容哈希和格式变化完整。
6. 使用含 Cookie、Authorization、凭据 URL 和完整剪贴板数据的夹具，确认这些值没有进入正文、来源记录、日志、索引或对象存储。

### 6. 详情页

1. 打开包含全部支持格式和图片的知识详情。
2. 确认内容、图片顺序、说明和替代文本正确。
3. 在桌面上打开图片放大视图。
4. 模拟图片加载失败，确认替代文本和安全占位出现。
5. 用恶意旧 HTML fixture 打开详情，确认脚本和远程资源不执行。

### 7. 搜索与 AI

1. 用标题、列表、代码、图片说明和替代文本中的词执行唯一搜索。
2. 确认知识条目命中并显示匹配原因。
3. 检查列表和搜索响应只含摘要 DTO，不携带完整 `bodyDocument`。
4. 请求 AI 整理，确认只发送纯文本投影。
5. 明确选择图片 OCR/vision，确认按 002 的唯一点数、报价和失败释放结算。
6. 同一图片重复出现或两个资产内容哈希相同时，确认 002 报价响应只返回一个唯一图片资源并只计费一次。

### 8. 双标签页冲突

1. 在两个标签页打开同一知识并分别修改。
2. 第一个标签页保存后，第二个标签页保存。
3. 确认冲突提示出现，可选择重新加载、另存新知识或明确覆盖。
4. 确认当前本地内容和图片引用不会无提示丢失。

### 9. 移动端与无障碍

1. 在 320、360、390、430 px 和横屏打开编辑器。
2. 使用软键盘、更多格式菜单、表格和图片调整，确认选区保留、主操作可达。
3. 使用 200% 字体、键盘和屏幕阅读器检查工具栏、表格、图片说明和错误。
4. 使用 Taste 在 1440、768、390、360 px 检查编辑和详情，确认手机详情没有页面级横向滚动。

### 10. 旧数据迁移与来源

1. 导入纯文本、多个空行、长链接和代码条目。
2. 执行迁移，确认段落和换行保留。
3. 重复执行和并发打开，确认无重复转换、重复图片或换行丢失。
4. 模拟迁移失败并重试，确认原纯文本可恢复。
5. 检查每条成功迁移均记录 `legacy_text` 来源、converter version、转换时间和转换报告；失败记录不得伪装为成功。
6. 迁移前详情响应允许 `bodyDocument=null` 并只读展示 `body`；迁移完成后才开放富文本编辑。

### 11. 清理与恢复

1. 删除正文中的图片引用，确认仍被其他条目使用的附件不受影响。
2. 永久删除条目，确认符合 001 的对象和回收站生命周期。
3. 恢复回收站条目，确认正文和图片引用恢复。
4. 扫描数据库、日志、索引和对象存储，确认没有未扫描原始图片或危险 HTML。
