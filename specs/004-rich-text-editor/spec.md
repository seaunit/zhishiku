# 功能规格说明：识海富文本知识编辑

**功能分支**：`004-rich-text-editor`

**创建日期**：2026-10-21

**状态**：草案

**输入**：知识库正文需要支持插入图片；手动采集和编辑时使用类似 Word 的富文本编辑器；查看知识详情时按照富文本格式显示。该能力必须与安全扫描、附件脱敏、移动端网页、搜索、AI 分析和现有单所有者架构保持一致。

## 范围与定位

本功能把知识正文从纯文本扩展为结构化富文本，并允许在正文中插入经过安全处理的图片。富文本用于手动采集和编辑，详情页使用相同的语义格式展示。

**MVP 范围**：

- 段落、标题、粗体、斜体、下划线、删除线、列表、引用、链接、代码和分隔线。
- 正文内嵌图片，支持从文件、相册和相机选择插入；拖放与编辑器内粘贴图片作为完整发布能力。
- 图片说明、替代文本、尺寸调整和对齐。
- 富文本详情安全展示、响应式图片和图片放大查看。
- 对搜索和 AI 提供派生纯文本，不把原始富文本标记作为外部模型输入。

**完整发布范围**：

- 从 Word、Google Docs 和网页粘贴后保留受支持的语义格式，并提供纯文本回退和来源报告。
- 图片拖放、编辑器内粘贴、表格创建/编辑、双标签页冲突处理和旧纯文本幂等迁移。

**不在范围内**：

- 完整文字处理器的分页、页眉页脚、脚注、多栏排版、任意字体、任意字号、任意颜色和打印版式。
- 实时多人协作、评论、修订模式、版本对比和共同编辑光标。
- 公式编辑器、绘图画布、复杂图表、嵌入电子表格或宏。
- 自动从外部网页下载图片，或绕过来源站点限制批量采集媒体。
- 在正文中执行脚本、嵌入可交互应用或运行粘贴内容携带的指令。

**与截图采集的关系**：正文内嵌图片是富文本编辑能力；独立的“截图”采集入口只接收剪贴板图片并作为知识来源处理。文档入口可上传文档和 JPG/PNG 等图片文件；上传的安全图片作为来源附件显示，只有用户明确操作时才插入正文。两者均沿用本功能及 001 的图片安全规则。

## 用户场景与测试 *（必需）*

### 用户故事 1 - 使用富文本编辑器整理知识（优先级：P1）

用户在手动采集或编辑知识时，可以使用清晰的格式工具栏创建标题、段落、列表、引用、链接和代码，并随时撤销或恢复操作。

**为何设置此优先级**：手动采集和编辑是知识库的基础入口，富文本必须让内容更易读而不是增加操作负担。

**独立测试**：创建一条新知识，依次应用标题、粗体、斜体、列表、引用、链接和代码，保存后重新打开并确认格式一致。

**验收场景**：

1. **假设**用户打开手动采集或编辑页面，**当**正文获得焦点，**则**显示与当前格式状态同步的工具栏和清晰的编辑区域。
2. **假设**用户选择文本并应用粗体、斜体、下划线或删除线，**当**操作完成，**则**所选范围立即显示对应格式，工具栏状态随之更新。
3. **假设**用户创建有序列表、无序列表、引用、链接或代码，**当**保存并重新打开，**则**内容结构和格式保持不变。
4. **假设**用户执行了格式化、删除、粘贴或图片调整，**当**使用撤销或重做，**则**最近操作按顺序恢复，不丢失其他正文。
5. **假设**用户选中了不受支持的文字样式，**当**执行“清除格式”，**则**保留文字内容并恢复为默认正文样式。

---

### 用户故事 2 - 在正文中插入和管理图片（优先级：P1）

用户可以从本地文件、相册、相机、拖放或粘贴插入图片，在正文中调整位置和大小，并填写说明和替代文本；图片必须先通过安全检查才能保存。

**为何设置此优先级**：正文图片是本次需求的核心能力，同时必须沿用知识库现有附件扫描和密钥脱敏门禁。

**独立测试**：在正文不同位置插入两张图片，调整顺序、尺寸和说明；模拟上传失败、密钥检测和扫描失败，确认安全与恢复行为。

**验收场景**：

1. **假设**用户点击插入图片，**当**选择本地文件、相册或相机图片，**则**图片显示上传和扫描状态，完成后出现在当前光标位置。
2. **假设**用户拖放或粘贴图片，**当**系统支持该输入方式，**则**图片进入相同安全扫描流程并插入正文，不绕过大小和格式限制。
3. **假设**图片通过安全扫描且未检测到密钥，**当**用户保存知识，**则**图片与正文保持稳定引用，重新打开时顺序和位置一致。
4. **假设**图片检测到高置信度密钥，**当**系统完成脱敏，**则**正文只使用脱敏派生图片并说明已处理，原始图片不进入持久存储。
5. **假设**图片无法完成完整扫描或脱敏，**当**用户尝试保存，**则**本次知识保存整体失败，不产生新知识版本或图片引用；其他文字和已安全图片只保留在当前未提交编辑区，用户可移除或替换失败图片后重新提交。
6. **假设**用户为图片填写说明或替代文本，**当**详情页显示或屏幕阅读器读取，**则**说明可见、替代文本可访问，并与图片保持关联。

---

### 用户故事 3 - 以富文本格式阅读知识详情（优先级：P1）

用户打开知识详情时，正文按照保存时的标题、段落、列表、链接、代码和图片格式展示，并在手机与桌面保持可读。

**为何设置此优先级**：只有详情页可靠还原格式，富文本编辑才形成完整价值闭环。

**独立测试**：打开包含全部支持格式和多张图片的知识详情，比较桌面与手机布局、图片顺序、链接、代码和替代文本。

**验收场景**：

1. **假设**知识包含标题、列表、引用、链接、代码和图片，**当**用户打开详情，**则**格式、顺序和层级与编辑器保存结果一致。
2. **假设**正文包含大尺寸图片，**当**在手机或窄窗口查看，**则**图片按容器缩放、保持比例且不撑破页面。
3. **假设**用户点击可查看图片，**当**打开放大视图，**则**可以看到完整图片、说明并关闭返回原阅读位置。
4. **假设**外部内容携带脚本、样式、表单或嵌入框架，**当**详情渲染，**则**这些主动内容不会执行或显示为受信任控件。
5. **假设**正文中的图片暂时无法加载，**当**用户阅读，**则**显示替代文本和安全占位，不影响其他正文。

---

### 用户故事 4 - 粘贴或导入已有富文本内容（优先级：P2）

用户从 Word、Google Docs 或网页复制内容时，系统保留标题、列表、链接和图片等受支持结构，移除脚本、跟踪内容和不安全样式，并提供纯文本回退。

**为何设置此优先级**：真实知识整理经常跨来源复制，但安全性必须先于格式保真。

**独立测试**：从包含标题、表格、图片、内联样式、脚本和远程图片的样本中粘贴，验证保留、降级、拒绝和纯文本回退。

**验收场景**：

1. **假设**用户从 Word 或 Google Docs 粘贴内容，**当**内容包含受支持的标题、列表、粗体、链接和表格，**则**保留语义结构并统一到识海样式。
2. **假设**粘贴内容包含脚本、事件属性、表单、内嵌框架、宏或危险链接，**当**系统处理，**则**主动内容被移除且不执行。
3. **假设**粘贴内容引用远程、`data:`、`blob:`、`cid:` 或 `file:` 图片，**当**内容进入编辑器，**则**系统不得发起图片网络请求或把来源作为可渲染内嵌图片，只保留未解析占位或安全来源链接，用户可主动上传替换。
4. **假设**粘贴内容格式无法可靠转换，**当**用户选择“粘贴为纯文本”，**则**文字、换行和链接地址按安全文本保留，不产生损坏的富文本结构。
5. **假设**用户粘贴大量复杂内容，**当**系统简化格式，**则**明确告知哪些格式被移除，正文文字不能因格式转换而丢失。
6. **假设**一次粘贴或旧文本转换成功，**当**用户查看来源或系统执行审计，**则**可以确认来源类型、清理后的来源 URL、采集时间、转换时间、converter version 和格式转换报告，且其中不包含 Cookie、Authorization、完整剪贴板或含凭据 URL。

---

### 用户故事 5 - 搜索、AI 和移动端正确使用富文本（优先级：P2）

用户可以通过富文本里的可见文字、图片说明和替代文本搜索知识；AI 只接收安全纯文本和明确引用的图片；手机上的工具栏和图片操作完整可用。

**为何设置此优先级**：富文本不能破坏现有单框检索、AI 授权、计费和移动网页。

**独立测试**：分别用标题、列表、表格、代码、图片说明和替代文本检索，并在手机与桌面执行富文本粘贴、图片插入和 AI 分析。

**验收场景**：

1. **假设**用户搜索正文标题、列表、引用、表格文字、代码、图片说明或替代文本中的词，**当**执行唯一搜索，**则**知识条目被正确匹配并显示匹配原因。
2. **假设**用户请求 AI 整理或分析，**当**发送内容，**则**只发送允许的纯文本投影和经授权图片，不发送原始富文本标记、脚本或未授权嵌入内容。
3. **假设**手机打开富文本编辑器，**当**工具栏、软键盘和安全区出现，**则**主要格式和插入图片入口可访问，工具栏不遮挡正文。
4. **假设**用户使用屏幕阅读器或键盘，**当**操作格式、链接、图片说明和销毁操作，**则**控件有名称、状态可播报、焦点顺序合理。
5. **假设**用户切换中文和英文，**当**使用富文本编辑器与详情页，**则**界面、格式名称、错误、图片说明和无障碍文本完整一致。
6. **假设**用户在 320 px 手机上仅使用触摸或键盘，**当**通过工具栏更多菜单、表格和图片调整完成全部支持格式，**则**文本选区保留、操作可达且焦点返回编辑位置。

### 边界情况

- 图片上传、扫描或脱敏期间，用户继续编辑其他正文或插入其他图片，不得导致内容顺序错乱。
- 用户删除正文中的图片引用时，不应立即删除仍被其他知识或正文位置使用的图片资源。
- 同一知识在两个标签页同时编辑时，后提交不得静默覆盖较新版本，必须保留本地内容并提供冲突处理。
- 富文本自动保存失败时，用户当前输入和格式不得被清空，必须显示明确可重试状态。
- 浏览器关闭、刷新或内存回收后，可恢复的草稿应保留安全文字和格式；未完成安全扫描的图片只保留元数据并要求重新选择。
- 粘贴内容包含超长嵌套列表、超大表格、深层引用或异常样式时，系统必须安全截断或降级，不得卡死编辑页。
- 复制内容包含隐藏文字、跟踪像素、外部字体或远程样式时，不得在未告知用户的情况下加载或保留。
- 正文包含大量图片时，详情页必须按需加载并提供稳定的占位尺寸，避免阅读位置跳动。
- 图片格式不受支持、文件损坏、方向信息异常、像素数超大或尺寸超限时，必须提示原因；本次提交不得保存，其他正文只保留在未提交编辑区。
- 图片替代文本为空时，用户应被提醒；若用户确认图片仅作装饰，可标记为装饰而不重复播报。
- 富文本链接指向本机、私网或其他非公开地址时，普通阅读展示必须按现有安全规则处理，不得自动访问。
- 搜索不应匹配原始富文本标签名或内部图片键，只匹配用户可见文字、图片说明和替代文本。
- 旧版纯文本知识首次打开时必须安全转换为富文本，换行、链接地址和代码内容不得丢失。
- 富文本内容超过正文或图片限制时，用户必须收到明确提示，已输入内容不得无提示截断。
- 移动端工具栏、键盘和图片缩放视图不得遮挡保存、取消和错误提示。
- 富文本详情不得因为粘贴或旧数据中的不安全标记执行脚本、发送网络请求或改变用户设置。
- 动画图片必须转换为明确的静态结果或拒绝，不得在正文中无提示播放动画。
- 同一图片资源在正文中出现多次时，详情可显示多个位置，但 AI 图片分析只对唯一安全资源执行一次。

## 需求 *（必需）*

### 编辑器与格式

- **FR-001**：手动采集和编辑页面必须使用富文本编辑器编辑知识正文。
- **FR-002**：编辑器必须支持段落、至少三级标题、粗体、斜体、下划线、删除线和清除格式。
- **FR-003**：编辑器必须支持有序列表、无序列表、引用、链接、行内代码、代码块和分隔线。
- **FR-004**：编辑器必须支持至少基本表格的创建、增删行列和单元格文字编辑；表格能力属于 P1 完整发布范围，MVP 只要求安全渲染已存在的合法表格。
- **FR-005**：编辑器必须支持撤销、重做和常用键盘快捷操作，并在工具栏显示当前可执行状态。
- **FR-006**：工具栏必须反映光标位置的当前格式，不能错误地把未应用格式显示为已启用。
- **FR-007**：用户必须能够将选中内容清除为默认正文格式，同时保留文字内容。
- **FR-008**：系统必须将视觉样式规范为知识库一致的字号、间距和颜色，不允许正文随意携带任意字体、字号或背景色。
- **FR-009**：编辑器必须支持从外部内容粘贴时选择保留格式或粘贴为纯文本。

### 内嵌图片

- **FR-010**：用户必须能够通过工具栏、文件选择、相册、相机、拖放和粘贴在正文光标处插入图片。
- **FR-011**：图片必须沿用现有附件安全规则，在完整扫描通过前不得进入持久正文或对象存储。
- **FR-012**：检测到高置信度密钥时，只能使用经过可靠脱敏的派生图片；无法可靠脱敏时必须拒绝该图片。
- **FR-013**：图片插入必须显示选择、上传、扫描、成功、失败、取消和重试状态。
- **FR-014**：任一图片无法完整扫描或脱敏时，本次知识保存整体失败，不得产生新知识版本、图片引用或对象提升；正文和其他图片只能保留在当前未提交编辑区，用户移除或替换失败图片后可重新提交。
- **FR-015**：用户必须能够在正文中移动图片位置、调整显示尺寸和对齐方式，并保持原始宽高比。
- **FR-016**：每张内嵌图片必须支持可编辑说明和替代文本；装饰性图片可以明确标记为无需替代文本。
- **FR-017**：图片必须以稳定引用与知识正文关联，重新打开、编辑和详情展示时保持顺序与位置。
- **FR-018**：外部网页图片不得由系统自动下载或绕过来源限制；用户必须主动上传，或以安全链接形式保留。
- **FR-019**：从正文移除图片引用后，图片资源必须按其他引用、回收站和保留期规则清理，不得误删其他知识仍在使用的图片。
- **FR-020**：MVP 每条知识最多包含 20 张内嵌图片、单个源文件不超过 25 MiB、处理后内嵌图片合计不超过 50 MiB；超限必须在保存前说明。
- **FR-021**：内嵌图片只接受经过安全验证的 JPEG、PNG、WebP 以及受支持手机浏览器提供的 HEIC/HEIF 相机图；HEIC/HEIF 必须规范化为可安全展示的静态格式，动画图片必须只保留第一帧或拒绝，不接受 SVG、脚本化图片、可执行内容或未处理的活动内容。
- **FR-049**：单张处理后图片每边不得超过 8192 像素且总解码像素不得超过 4000 万；超过时必须在保持宽高比的前提下安全缩小或拒绝，并在保存前说明。
- **FR-050**：图片必须根据方向信息正确显示，持久化前移除不必要的 EXIF、XMP 和其他可识别元数据，同时不得改变图片可见内容的朝向。
- **FR-051**：脱敏派生图必须验证为与原始图片对应且不包含原始敏感区域；验证不通过时整次保存失败。

### 详情展示

- **FR-022**：知识详情必须按保存时的语义格式显示正文，不使用编辑器控件覆盖阅读内容。
- **FR-023**：详情中的图片必须响应容器宽度、保持比例、按需加载，并提供稳定的布局占位。
- **FR-024**：用户必须能够打开图片放大视图查看完整图片、说明并关闭返回阅读位置。
- **FR-025**：图片无法加载时必须显示替代文本和安全占位，不得阻断其他正文。
- **FR-026**：详情必须支持手机窄屏、平板、桌面、横屏和系统大字体，不产生页面级横向滚动。
- **FR-027**：详情中的链接、代码、表格和长文本必须使用安全且可读的换行或局部滚动方式。
- **FR-028**：富文本内容中的脚本、事件处理、表单、嵌入框架、跟踪内容和危险链接不得执行或作为受信任内容展示。
- **FR-052**：详情只能自动加载系统内已完成安全扫描的图片引用；历史或粘贴数据中的远程 URL、`data:`、`blob:`、`cid:`、`file:`、动画和脚本化 SVG 一律不得自动请求或作为内嵌图片执行。

### 粘贴、转换与数据

- **FR-029**：系统必须支持从 Word、Google Docs 和网页粘贴受支持的语义格式。
- **FR-030**：粘贴内容必须转换为允许的格式集合；不支持或危险内容必须移除、降级或拒绝，不得原样存储和执行。
- **FR-031**：系统必须提供纯文本粘贴回退，保留文字、换行和可见链接地址。
- **FR-032**：转换导致格式丢失时，必须向用户说明被移除的格式类型，且不得丢失文字内容。
- **FR-033**：富文本正文必须保存格式结构、内容版本和安全状态，以实现可验证的保存与重新渲染。
- **FR-034**：系统必须生成不含富文本标记的可见纯文本投影，用于搜索、摘要和 AI 文本输入。
- **FR-035**：纯文本投影必须包含正文可见文字、列表内容、引用、表格文字、代码、图片说明和图片替代文本。
- **FR-036**：旧版纯文本知识必须安全转换为富文本，保留段落、换行和可识别链接，不得伪造新格式。
- **FR-037**：保存富文本时必须执行版本冲突检查，阻止旧页面静默覆盖较新内容；冲突时用户必须能够选择重新加载最新版本、将本地版本另存为新知识，或查看差异后明确覆盖，图片引用和本地未提交内容必须保留到用户作出选择。
- **FR-038**：富文本自动保存或手动保存失败时，用户当前内容和可恢复草稿必须保留。
- **FR-039**：每次成功保存必须更新搜索和 AI 使用的纯文本投影，不得继续使用旧正文。
- **FR-040**：知识进入回收站或永久清除时，正文、内嵌图片关系和未共享图片资源必须遵循现有生命周期规则。

### 搜索、AI 与移动端

- **FR-041**：唯一搜索框必须匹配富文本可见文字、图片说明和替代文本，并说明匹配原因。
- **FR-042**：搜索不得匹配内部格式标签、图片存储键、隐藏样式或原始不安全标记。
- **FR-043**：AI 只接收纯文本投影和用户明确授权的图片引用，不接收原始富文本标记或脚本。
- **FR-044**：内嵌图片参与 AI 分析时，必须继续遵守外部服务授权、内容类型授权、计费报价和失败不扣费规则；默认文本整理不分析图片，用户明确选择图片分析或 OCR 时才计入每张唯一图片 10 点的报价，同一图片在正文重复出现只计一次。
- **FR-045**：移动端富文本工具栏必须在 320 至 430 CSS 像素内可用，主要控件至少 44×44 CSS 像素，不遮挡正文或软键盘；放不下的格式进入“更多”菜单或局部滚动工具栏，打开菜单和返回编辑器时必须保留文本选区。
- **FR-046**：富文本编辑器、图片操作和详情页必须支持键盘、屏幕阅读器和可见焦点。
- **FR-047**：中英文界面必须为格式、图片、错误、提示和替代文本编辑提供完整一致文案。
- **FR-048**：富文本保存和详情展示不得改变桌面布局、移动端要求、价格、点数、隐私授权或原有拾题应用的 `/`、`/app`、`/api`、`/bank`、`/pay`、`/apk`、认证、Cookie、证书和支付 sidecar；图片上传限制只能在 `/kb` 范围内调整，部署失败必须可回滚。
- **FR-053**：表格必须具有可识别的表头、行列关系和键盘导航；窄屏可以局部滚动表格，但不得撑宽整页。
- **FR-054**：图片尺寸、对齐和说明必须提供键盘可访问的等价操作，不得只依赖拖动或鼠标。
- **FR-055**：旧版纯文本转换必须幂等；重复打开或并发打开不得重复改写内容、丢失换行或创建重复图片资源，转换失败必须保留原文并可重试。
- **FR-056**：旧数据转换、正文取消图片引用和回收站清除必须按引用关系清理图片资源，不得产生孤儿资源或误删其他知识仍在使用的图片。
- **FR-057**：每次成功粘贴、外部内容转换或旧文本迁移必须独立记录来源类型、清理后的 HTTP/HTTPS 来源 URL、采集时间、转换时间、converter version、安全内容哈希和格式转换报告；这些信息不得混入正文可见内容，不得包含 Cookie、Authorization、完整剪贴板、原始 HTML 或含凭据 URL。

### 关键实体 *（如涉及数据）*

- **富文本文档**：知识正文的结构化格式内容，包含格式版本、安全处理状态、创建和更新时间。
- **富文本块**：段落、标题、列表、引用、代码、分隔线、表格或图片等内容单元，包含顺序和语义格式。
- **内嵌图片引用**：正文中的图片位置，包含图片资源引用、说明、替代文本、显示尺寸、对齐和安全状态。
- **富文本纯文本投影**：从可见正文和图片文本派生的搜索与 AI 输入，不包含内部标记、脚本或存储键。
- **格式转换报告**：外部粘贴或旧数据转换时保留、降级、移除和拒绝的格式摘要。

## 假设

- 富文本主要应用于知识正文；标题、分类、标签、备注和来源元数据保持原有字段职责。
- 富文本格式采用有限、语义化的知识排版集合，不追求完整 Word 排版能力。
- 基本表格属于完整发布能力，但可以在核心文字和图片编辑之后交付。
- 图片继续作为安全扫描后的附件资源管理，正文只保存稳定引用和展示属性。
- 内嵌图片默认限制为每条 20 张、单图源文件 25 MiB、处理后合计 50 MiB；正文纯文字上限沿用现有知识正文限制。
- 支持的静态图片包括 JPEG、PNG、WebP 和受支持 iOS Safari 提供的 HEIC/HEIF；处理后每边不超过 8192 像素、总像素不超过 4000 万，动画图片只保留第一帧或拒绝。
- 从外部粘贴时优先保留受支持的语义结构；视觉样式统一为识海设计系统，不保留任意字体、字号和颜色。
- 外部图片不会由系统自动下载；用户需主动上传，或以安全链接保留来源。
- 搜索和 AI 使用派生纯文本，不解析或执行富文本标记。
- 富文本必须同时满足移动网页和桌面要求，并使用 Taste 进行真实浏览器检查。
- 桌面端纯文本知识可以安全转换，不要求用户手工重建全部内容。
- 完整性扫描采用全次拒绝：任一图片失败会使本次保存失败，但不删除当前未提交编辑器内容。
